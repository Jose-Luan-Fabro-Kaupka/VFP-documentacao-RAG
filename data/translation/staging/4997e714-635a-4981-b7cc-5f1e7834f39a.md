# Atualizando Dados Remotos com SQL Pass-Through

Quando você usa funções SQL pass-through para atualizar dados em um servidor remoto, controla se os dados são atualizados, bem como detalhes específicos sobre as atualizações, definindo propriedades no cursor do conjunto de resultados. O Visual FoxPro verifica essas propriedades quando uma atualização é solicitada antes de confirmar a atualização.

> **Dica:** Cursors de view SQL pass-through não são atualizáveis até que você especifique propriedades de atualização para o cursor da view. Se deseja armazenar configurações de propriedades de atualização de forma persistente, crie uma definição de view. O Visual FoxPro fornece valores padrão que preparam a view para ser atualizável quando você cria uma view usando o View Designer ou a linguagem. Você pode usar a função CURSORSETPROP() para adicionar informações adicionais para complementar ou personalizar os valores padrão.

Para atualizar dados remotos, você deve definir as seguintes propriedades usando a função CURSORSETPROP( ):
 - Tables
- KeyFieldList
- UpdateNameList
- UpdatableFieldList
- SendUpdates

Você pode especificar propriedades adicionais, como Buffering, UpdateType e WhereType, para melhor atender aos requisitos de sua aplicação.

As propriedades de atualização que você define no cursor da view ativa têm nomes ligeiramente diferentes de suas contrapartes da DBSETPROP( ) Function. A tabela a seguir lista os nomes usados para definições de view e cursors ativos.
 Propriedades de Atualização de View e Cursor
| Finalidade | Propriedades de definição de view1 | Propriedades de cursor ativo2 |
| --- | --- | --- |
| Tornar tabela remota atualizável. | Tables | Tables |
| Especificar os nomes remotos para campos da view. | UpdateName (propriedade de nível de campo) | UpdateNameList |
| Especificar campos da view que deseja usar como chaves. | KeyField (propriedade de nível de campo) | KeyFieldList |
| Especificar os campos da view que são atualizáveis. | Updatable (propriedade de nível de campo) | UpdatableFieldList |
| Ativar atualizações. | SendUpdates | SendUpdates |

1 Definido com DBSETPROP( ). 2 Definido com CURSORSETPROP( ).

Para obter mais informações sobre como definir propriedades de atualização, consulte How to: Update Data in a View, ou consulte DBSETPROP( ) Function ou CURSORSETPROP( ) Function.

# Controlando o Momento das Atualizações Remotas

Você controla como as atualizações de dados remotos são colocadas em buffer definindo a propriedade Buffering do cursor. Das cinco configurações possíveis da propriedade buffering, duas são válidas para views remotas:
 - 3, ou DB_BUFOPTROW, o padrão, que bloqueia otimisticamente a linha.
- 5, ou DB_BUFOPTTABLE, que bloqueia otimisticamente a tabela.

O Visual FoxPro suporta apenas bloqueio otimista em cursors remotos.

> **Observação:** As configurações de buffer pessimista de linha e tabela, 2 e 4, não se aplicam a views remotas, porque o Visual FoxPro não obtém bloqueios nos dados do servidor. A configuração 1 da propriedade Buffering não se aplica a views remotas porque views estão sempre em buffer.

# Usando Buffer Otimista de Linha

A configuração padrão Buffering, DB_BUFOPTROW, bloqueia otimisticamente dados remotos linha a linha. Por exemplo, se você deseja que alterações na tabela `titles` sejam confirmadas linha a linha, como ao usar o comando SKIP, você pode definir a propriedade Buffering como 3:

```foxpro
CURSORSETPROP('buffering', 3, 'titles')
```

Quando Buffering está definido como buffer de linha, você tem dois métodos de enviar atualizações ao servidor remoto. Você pode:
 - Chamar a função TABLEUPDATE( ).
- Usar um comando que move o ponteiro de registro para fora da linha, como SKIP ou GO BOTTOM .

A função TABLEUPDATE( ) atualiza o servidor sem mover o ponteiro de registro. Comandos que movem o ponteiro de registro enviam atualizações ao servidor remoto como subproduto de sair do registro atualizado.

Se você usar buffer de linha e desejar poder reverter alterações em linhas, deve envolver as alterações em transações manuais usando funções de transação SQL pass-through.

# Usando Buffer Otimista de Tabela

Se você deseja que alterações em uma tabela sejam confirmadas em lote, como quando o usuário clica em um botão Save ou OK em um formulário, pode definir a propriedade Buffering como 5, ou DB_BUFOPTTABLE. Você deve chamar a função TABLEUPDATE( ) para enviar a atualização ao servidor.

No exemplo a seguir, você define a propriedade Buffering no código de inicialização do formulário e confirma as alterações no código de salvamento.

| Código | Comentários |
| --- | --- |
| CURSORSETPROP('buffering', 5, 'sqltitles') | Definido no código Init |
| * Update batched changes; * ignore changes made by others | |
| TABLEUPDATE(.T., .T., 'titles') | Definido no código Save |

Para restaurar os valores originais em uma tabela e impedir que atualizações sejam enviadas ao servidor remoto, você chama a TABLEREVERT( ) Function. Você pode controlar se uma única linha ou todas as linhas são revertidas combinando a configuração da propriedade Buffering do cursor com o comando TABLEREVERT( ). O exemplo a seguir reverte apenas a linha atual. Você pode querer invocar este código quando o usuário clica em um botão Cancel em um formulário:

```foxpro
= TABLEREVERT(.F., 'titles')      && Revert current row
```

Se você deseja reverter todas as linhas, como quando o usuário pressiona ESC para sair de um formulário, pode usar o mesmo exemplo, alterando as configurações da propriedade Buffering e do comando TABLEREVERT( ) para reverter todas as linhas, com a tabela inteira em buffer:

```foxpro
= TABLEREVERT(.T., 'titles')      && Revert all rows
```

Para obter mais informações sobre buffer, consulte Programming for Shared Access.

# Detectando Alterações de Outros Usuários

Em aplicações multiusuário, conflitos com atualizações de outros usuários são detectados pela consulta SQL Update, que é gerada quando uma gravação é tentada localmente. O nível de detecção depende da configuração da propriedade WhereType. Para obter mais informações sobre como definir a propriedade WhereType, consulte Managing Updates by Using Views.

# Forçando Atualizações

Você pode usar a TABLEUPDATE( ) Function para controlar se alterações feitas em uma tabela ou cursor por outro usuário em uma rede são substituídas quando você envia suas atualizações. Se você definir o parâmetro Force de TABLEUPDATE( ) como true (.T.), e a propriedade UpdateType da CURSORSETPROP( ) Function estiver definida como o valor padrão, 1, os dados antigos são atualizados com os novos dados que você envia, desde que o valor no campo chave do registro na tabela remota não tenha sido alterado. Se o valor no campo chave da tabela remota foi alterado, ou se a propriedade UpdateType está definida como 2, o Visual FoxPro envia uma instrução DELETE e depois uma instrução INSERT para a tabela remota.

# Solucionando Mensagens de Erro de Atualização

A tabela a seguir lista as mensagens de erro Visual FoxPro e ODBC que se aplicam especificamente a atualizações remotas. A coluna Action contém a ação que você executa para resolver a condição de erro.

| Mensagem de Erro | Significado | Ação |
| --- | --- | --- |
| No update table(s) specified. Use the Tables cursor property. | A propriedade Tables do cursor não contém nomes de tabelas remotas. Pelo menos uma tabela é necessária para habilitar atualizações no servidor remoto. | Use a propriedade Tables para especificar pelo menos uma tabela para o cursor. |
| No key column(s) specified for the update table table_name . Use the KeyFieldList cursor property. | A chave primária da tabela remota especificada na mensagem de erro não está incluída na propriedade KeyFieldList do cursor; uma chave primária é necessária para cada tabela sendo atualizada. | Use a propriedade KeyFieldList para especificar a chave primária da tabela remota. |
| No valid update table specified for column column_name . Use the UpdateNameList and Tables cursor properties. | A propriedade UpdateName para a coluna column_name tem um qualificador de tabela inválido. | Defina o qualificador de tabela com a propriedade UpdateNameList, ou adicione o qualificador de tabela à configuração da propriedade Tables, ou ambos. |
| The KeyField List cursor property doesn't define a unique key. | Mais de um registro remoto tem a mesma chave. | Use a propriedade KeyField List para definir uma chave exclusiva para a tabela remota. |
| From ODBC: ODBC invalid object. | ODBC não pode encontrar a tabela ou coluna remota porque ela não existe conforme nomeada. Nomes de campos Visual FoxPro são validados pelo Visual FoxPro; nomes de tabelas e colunas remotas são validados apenas pelo servidor remoto. | Verifique o nome do objeto. |

Para obter mais informações sobre tratamento de erros, consulte Handling SQL Pass-Through Errors.
