# Bandas de Relatório

As bandas de relatório permitem especificar onde e quando os dados são exibidos na página do relatório ou etiqueta. Por exemplo, suponha que você crie uma lista de contatos ordenada por sobrenomes. Você pode usar bandas de relatório para organizar as informações neste relatório. A lista a seguir contém alguns tipos possíveis de informação para os quais você pode querer designar bandas diferentes:
 - O nome da lista usando uma banda title, que aparece uma vez no início de um relatório.
- O número total de entradas na lista usando uma banda summary, que aparece no final de um relatório.
- O nome do relatório, número da página e data usando bandas page header ou page footer, que aparecem no início ou no final de cada página, respectivamente.
- Um separador entre os sobrenomes de contatos que começam com cada letra do alfabeto, para facilitar a localização de entradas, usando bandas group header e footer, que aparecem cada vez que o relatório passa para um registro em que a primeira letra do sobrenome do contato muda.

Você pode incluir os mesmos tipos de controles de relatório em todos os tipos de bandas de relatório, como controles Field e expressões calculadas para exibir dados. Para obter mais informações sobre controles de relatório, consulte Working with Report Controls.

Você escolhe diferentes tipos de bandas de relatório e coloca diferentes tipos de controles de relatório em cada banda para apresentar seus dados de forma eficaz. As seções a seguir contêm mais informações sobre tipos de bandas de relatório e sua estrutura:

# Tipos de Bandas de Relatório

Os relatórios contêm várias bandas por padrão; no entanto, você pode adicionar outras bandas ao relatório ou etiqueta. A tabela a seguir resume os tipos de bandas de relatório disponíveis e sua ordem aproximada no layout da página. Como as bandas podem se estender lateralmente, a tabela também indica quais bandas permitem continuar seu conteúdo em várias páginas se o conteúdo ultrapassar uma única página.

| Tipo de banda | Descrição | Disponibilidade no layout | Normalmente exibe | Pode abranger mais de uma página |
| --- | --- | --- | --- | --- |
| Title | Exibe informações ou dados que aparecem uma vez no início do relatório. | Banda opcional, pode ser colocada em página separada no início do relatório ou imediatamente antes da banda Page Header na primeira página. | Título do relatório ou página de título, data do relatório, número da página, logotipo da empresa, borda do título. | Não |
| Page Header | Exibe informações ou dados que aparecem uma vez por página no início da página. Disponível por padrão. | Banda obrigatória em todas as páginas, exceto quando as bandas Title e Summary estão em páginas separadas. Opcionalmente disponível na página Summary. | Nome do relatório, número da página, data do relatório. | Não |
| Column Header | Exibe informações ou dados que aparecem uma vez por conjunto de colunas precedendo o conjunto de colunas. | Adicionada automaticamente para cada coluna criada pelo usuário. Não aparece quando o relatório tem apenas uma coluna. | Prefácio ao conjunto de colunas. | Não |
| Group Header | Exibe informações ou dados que aparecem uma vez por grupo precedendo o grupo. | Adicionada automaticamente para cada grupo de dados criado pelo usuário. | Prefácio a um grupo de dados. | Sim |
| Detail Header | Exibe informações ou dados que aparecem uma vez por registro precedendo o registro. Adicionada pelo usuário. | Banda opcional, disponível para cada Detail Band no layout. | Prefácio a um registro. | Sim |
| Detail | Exibe informações ou dados que aparecem uma vez por registro na tabela subjacente. Disponível por padrão. | Uma Detail Band é obrigatória no layout do relatório. O usuário pode incluir opcionalmente Detail Bands adicionais. | Dados para cada registro. | Sim |
| Detail Footer | Exibe informações ou dados que aparecem uma vez por registro após o registro. | Banda opcional, disponível para cada Detail Band no layout. | Resumo do registro. | Sim |
| Group Footer | Exibe informações ou dados que aparecem uma vez por grupo após o grupo. | Adicionada automaticamente para cada grupo de dados criado pelo usuário. | Valores calculados para um grupo de dados. | Sim |
| Column Footer | Exibe informações ou dados que aparecem uma vez por conjunto de colunas após o conjunto de colunas. | Adicionada automaticamente para cada coluna criada pelo usuário. Não aparece quando o relatório tem apenas uma coluna. | Resumo, totais de coluna. | Não |
| Page Footer | Exibe informações ou dados que aparecem uma vez por página no final de uma página. | Banda obrigatória em todas as páginas, exceto quando as bandas Title e Summary estão em páginas separadas. Opcionalmente disponível na página Summary. | Nome do relatório, número da página, data do relatório. | Não |
| Summary | Exibe informações ou dados que aparecem uma vez no final do relatório. | Banda opcional, pode ser colocada em uma página separada no final do relatório ou imediatamente antes da banda Page Footer na última página. | Totais do relatório, página de resumo. Observação Você pode criar totais gerais colocando expressões calculadas na banda Summary. | Sim |

# Escolhendo Diferentes Tipos de Banda para Conteúdo de Relatório

O uso das bandas Title e Summary é facilmente compreendido comparando essas seções do relatório à estrutura de um livro.

A banda Title contém informações que aparecem apenas uma vez no início do relatório, semelhante à matéria preliminar de um livro, como prefácio, agradecimentos ou índice. A Summary contém informações encontradas apenas no final do livro, como seu índice ou colofón.

Page Headers e Page Footers também são semelhantes aos de um livro. O título do livro pode aparecer na margem superior de cada página, e o número da página pode aparecer na margem inferior. Embora livros frequentemente não tenham Column Headers e Column Footers, o uso dessas bandas também é claro a partir de sua posição física no layout da página.

No entanto, quando um relatório contém várias Detail bands e grupos de dados, essas bandas parecem semelhantes no layout do relatório. Sua diferença de estrutura no relatório pode não ser clara inicialmente. Além disso, em tempo de execução, essas bandas não aparecem sempre nos mesmos locais físicos em que apareceram durante o design do relatório ou etiqueta.

Você pode pensar em Group Headers e Group Footers como tendo um papel semelhante aos parágrafos introdutórios e resumos que você pode encontrar em cada capítulo de um livro. As detail bands são análogas aos parágrafos que aparecem entre essas seções preparatórias e conclusivas do capítulo; podem aparecer qualquer número de vezes antes do capítulo terminar.

A seção a seguir explica as diferenças entre Detail bands e Group bands com mais detalhes.

# Comparando Group e Detail Bands em Layouts de Relatório

Quando você adiciona Detail bands, elas aparecem consecutivamente no layout da página. Aparecer consecutivamente significa que cada nova Detail band é adicionada após a última Detail band, e cada conjunto de Detail Header e Detail Footer bands aparece com a Detail band correspondente. Uma Detail band e suas Detail Header e Detail Footer bands correspondentes compõem um conjunto de detail band; nenhuma outra banda pode separá-las. A estrutura consecutiva de vários conjuntos de detail band permite incluir dados de várias tabelas filhas de um único pai. O Target alias de uma Detail band informa ao Report Engine qual conjunto de registros filhos relacionados você deseja processar nesta banda. Consulte How to: Specify Target Aliases for Detail Bands para obter mais informações.

Quando você adiciona grupos de dados, eles e suas Group Header e Group Footer bands correspondentes aparecem aninhados no layout da página. Aparecer aninhado significa que o primeiro grupo de dados criado aparece no nível mais externo no layout da página, enquanto o último grupo de dados criado aparece no nível mais interno. A estrutura aninhada dos grupos de dados permite agrupar registros em relatórios baseados em uma relação avô-pai-filho. A expressão Group on de um grupo de dados informa ao Report Engine quando iniciar um novo grupo. Para obter mais informações, consulte How to: Add Data Groups to Reports.

# Diferenças Funcionais entre Group e Detail Bands

As diferentes formas como o Report Designer exibe conjuntos de Detail band e grupos de dados refletem suas diferentes funções em tempo de execução. Os dois tipos de bandas ajudam a exibir diferentes tipos de relações de dados em relatórios.

Por exemplo, suponha que você tenha uma tabela de clientes com duas tabelas filhas, orders e payments. Usando várias Detail bands, você pode criar um relatório contendo os pedidos e pagamentos de cada cliente. Os pedidos e pagamentos não estão relacionados entre si, porque as entradas nas tabelas orders e payments não correspondem necessariamente uma à outra de qualquer forma.

No mesmo relatório de exemplo, suponha que você tenha uma tabela SalesPeople, com cada vendedor sendo responsável por um ou mais clientes. Usando um grupo de dados, você pode aninhar os detalhes dos clientes de cada vendedor dentro de um cabeçalho ou rodapé mostrando o nome do vendedor. Em outra tabela, você armazena os nomes dos territórios de vendas, com cada território sendo atendido por um ou mais clientes. Você pode aninhar o grupo SalesPeople dentro de um grupo externo exibindo informações sobre cada território.

As bandas Group ocorrem quando sua expressão Group on muda durante o relatório. No relatório de exemplo descrito acima, a expressão de grupo pode ser `territory` ou `salesperson`. Um grupo de dados de relatório requer uma expressão Group on. Detail bands têm uma expressão Target alias opcional, que pode parecer uma expressão Group on, mas é bem diferente. No relatório de exemplo, as expressões Target alias são `"orders"` e `"payments"` ou variáveis referenciando os aliases sob os quais cada tabela filha está aberta.

Para obter mais informações, consulte Working with Report Data Groups e Working with Related Tables using Multiple Detail Bands in Reports.

Conjuntos de detail band e bandas de grupo têm algumas diferenças funcionais adicionais em relatórios:
 - É impossível ter o Report Engine avaliar um grupo de dados sem um Group Header e Group Footer no layout, representando a expressão Group on correspondente. Detail Header e Group Footer bands são bandas opcionais; uma Detail band pode constituir um conjunto de detail band sem elas.
- Se você incluir as Detail Header e Detail Footer bands opcionais para uma detail band, essas bandas podem aparecer em seu relatório mesmo se a tabela filha especificada pelo target alias da banda não tiver registros correspondentes ao registro pai atual. Esta condição é impossível para Group Headers e Group Footers, pois um grupo não pode existir sem pelo menos uma linha de detalhe satisfazendo a expressão Group on do grupo. Dica Se você não deseja que controles de relatório nas Detail Header e Detail Footer sejam exibidos quando a Detail band não tem conteúdo, pode usar expressões Print when para suprimi-los. Geralmente a expressão correta a usar neste cenário é EOF(<target alias>) , onde <target alias> é a expressão Target alias que você usou para esta Detail band. A função EOF() indica quando o ponteiro de registro é colocado no final do arquivo para esta tabela filha durante a execução do relatório porque não há registro filho válido. Você pode fechar o espaço vazio nas Detail Header e Detail Footer bands, quando esses controles de relatório não imprimem, usando a opção de cada controle Remove line if blank . Consulte How to: Suppress Blank Lines in Report Controls e Print When Tab, Report Control Properties Dialog Box (Report Builder) para obter mais informações.
- A palavra-chave SUMMARY nos comandos REPORT FORM e LABEL FORM suprime conjuntos de detail band, incluindo Detail Header e Detail Footer bands. Se você especificou expressões para avaliar na entrada ou na saída para essas bandas, elas não são disparadas durante uma execução de relatório SUMMARY. SUMMARY não suprime Group Headers e Group Footers, e suas expressões on entry ou on exit são avaliadas. Para obter mais informações, consulte How to: Specify Expressions to Evaluate When Processing Bands .
- Relatórios têm um limite de 74 grupos de dados aninhados e um limite separado de 20 conjuntos de Detail band. Criar conjuntos de detail band não subtrai do número disponível de grupos de dados, e criar grupos de dados não limita o número de conjuntos de detail band que você pode adicionar ao seu relatório.
