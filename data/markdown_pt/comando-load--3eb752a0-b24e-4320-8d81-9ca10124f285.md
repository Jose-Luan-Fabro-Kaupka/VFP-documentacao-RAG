# Comando LOAD

Não está mais disponível. Use o comando SET LIBRARY em vez disso.

Coloca um arquivo binário, comando externo ou função externa na memória.

```foxpro
LOAD file [FUNCTION]
	[SAVE] [NOSAVE]
```

#### Parâmetros
 file

 No FoxPro para MS-DOS e FoxPro para Windows, file é o nome do arquivo a ser carregado na memória. A extensão padrão para um arquivo binário é .BIN. Quando você chama uma rotina binária, omita a extensão. Se um arquivo que você carrega tiver o mesmo nome de arquivo de um arquivo carregado anteriormente, mas uma extensão de nome de arquivo diferente, o novo arquivo substitui o arquivo carregado anteriormente.

 No FoxPro para Macintosh, use file para especificar o comando externo ou função a ser colocada na memória.

FUNCTION

 No FoxPro para Macintosh, você deve incluir FUNCTION ao carregar uma função externa (XFNC) na memória.

SAVE

NOSAVE

 No FoxPro para MS-DOS e FoxPro para Windows, LOAD e CALL suportam palavras-chave opcionais para uso com rotinas binárias que gravam na janela principal do FoxPro.

 SAVE e NOSAVE são ignorados no FoxPro para Macintosh.

 Você pode incluir SAVE (NOSAVE é o padrão) ao carregar uma rotina binária, ou SAVE e NOSAVE ao chamar uma rotina binária. Se forem incluídos com CALL, SAVE e NOSAVE substituem a palavra-chave incluída com LOAD.

 Se SAVE for incluído, o FoxPro copia o conteúdo atual da RAM de vídeo na janela principal do FoxPro ao retornar da rotina binária (supondo que a rotina binária esteja gravando diretamente na RAM de vídeo).

 Isso significa que qualquer coisa gravada na janela principal do FoxPro pela rotina binária é conhecida pelo FoxPro e é tratada como se o FoxPro a tivesse gravado. Em particular, esses dados gravados externamente não são apagados quando um objeto FoxPro é arrastado sobre eles.

 A menos que seja necessário, não inclua SAVE, porque o FoxPro leva algum tempo para examinar e salvar o conteúdo da tela a cada retorno da rotina binária.

Criando um arquivo binário

----------------------

Siga estas etapas ao criar um arquivo binário para FoxPro para MS-DOS e FoxPro para Windows:

1. Monte o programa e crie um arquivo objeto com este comando:

 MASM file

2. Vincule o arquivo objeto e crie um arquivo executável com este comando:

 LINK file

3. Crie um arquivo binário com este comando:

 EXE2BIN file

Além disso, siga estas regras ao criar um arquivo binário FoxPro:

 A primeira instrução executável deve originar-se em um deslocamento de 0.

 O programa binário não deve alterar o comprimento das variáveis de memória passadas como argumentos.

 A quantidade de memória usada ou alocada não pode exceder o tamanho real do programa, porque o tamanho do arquivo é usado para determinar a quantidade de memória alocada.

 Os registradores SS e CS devem ser restaurados antes que o controle seja retornado ao FoxPro.

 Um retorno far deve ser usado para retornar o controle ao FoxPro quando o programa é executado com LOAD e CALL.

 Quando um programa é encerrado por uma chamada de sistema exit em vez de um retorno far, você deve executar programas de assembly com o comando RUN.

# Observações

No FoxPro para MS-DOS e FoxPro para Windows, use LOAD para colocar rotinas binárias do disco na memória. Um máximo de dezesseis arquivos de 64K pode ser carregado na memória de uma vez.

No FoxPro para Macintosh, use LOAD para colocar um comando externo ou função externa na memória. Um comando externo ou função colocado na memória com LOAD pode então ser executado com CALL. Um máximo de dezesseis comandos externos ou funções pode ser carregado na memória de uma vez.

Antes que um comando externo ou função possa ser colocado na memória com LOAD, o arquivo de recurso de comando externo contendo o comando externo ou função deve ser aberto com SET XCMDFILE.
