# Recursos de controle de código-fonte

O Visual FoxPro fornece vários recursos que suportam o desenvolvimento em equipe. Um recurso significativo do desenvolvimento em equipe é o uso de um sistema de controle de código-fonte para coordenar quem pode acessar e modificar arquivos em um projeto.

Controle de código-fonte é o termo genérico para ferramentas que gerenciam arquivos em um ambiente com vários desenvolvedores. A maioria das ferramentas de controle de código-fonte funciona de forma semelhante a uma biblioteca pública tradicional, mantendo um repositório central de arquivos — documentos, programas ou quaisquer outros arquivos — em um local acessível a todos os desenvolvedores. Além disso, as ferramentas de controle de código-fonte incluem a capacidade de rastrear as alterações que os desenvolvedores fazem nos arquivos e reverter a versões anteriores, se necessário.

De modo geral, as ferramentas de controle de código-fonte fornecem alguns ou todos estes recursos:
 - Check out, check in Desenvolvedores fazem check-out de um arquivo baixando uma cópia do repositório central para seu computador local antes de modificá-lo. Como regra, enquanto um arquivo está em check-out, outros desenvolvedores não podem fazer check-out ou modificá-lo, mas geralmente podem visualizá-lo sincronizando ou obtendo uma cópia somente leitura. (Se o arquivo é um arquivo de texto, como código-fonte de programa, é possível que vários desenvolvedores façam check-out do mesmo arquivo e depois mesclem as alterações de outros com sua cópia local.) Quando os desenvolvedores terminam com um arquivo, podem fazer check-in de suas alterações enviando sua cópia local ao repositório central. Como parte do processo de check-in do arquivo, a maioria das ferramentas de controle de código-fonte solicita que o desenvolvedor insira comentários sobre as alterações feitas no arquivo.
- Mesclagem Para permitir que vários desenvolvedores trabalhem simultaneamente no mesmo arquivo, o software de controle de código-fonte permite que vários desenvolvedores façam check-out do arquivo ao mesmo tempo. (Isso geralmente só pode ser feito com arquivos de texto, como código-fonte de programa.) Se outro desenvolvedor alterou o arquivo, o sistema de controle de código-fonte pode integrar essas alterações em sua versão do arquivo.
- Controle de projeto Desenvolvedores podem organizar arquivos em projetos ou outras categorias específicas de trabalho. Arquivos frequentemente podem ser compartilhados entre projetos, se necessário.
- Rastreamento de alterações A maioria dos sistemas de controle de código-fonte mantém registro das alterações feitas em um arquivo quando ele é feito check-in. Isso permite que os desenvolvedores reconstruam versões anteriores do arquivo, o que é útil para recuperar trabalho anterior.
- Verificação de diferenças O software de controle de código-fonte permite que os desenvolvedores comparem versões de um arquivo e revisem as diferenças entre elas.
- Histórico Desenvolvedores podem examinar o histórico de check-in de cada arquivo, incluindo os comentários feitos por cada desenvolvedor ao fazer check-in do arquivo. Dica Se seu software de controle de código-fonte suporta comentários, aproveite isso. Comentários podem auxiliar muito no processo de rastreamento de alterações e fornecer um histórico útil do desenvolvimento da aplicação.

Para usar controle de código-fonte, os usuários devem ingressar em um projeto controlado por código-fonte (às vezes referido como "enlistar" em um projeto). Quando os usuários ingressaram em um projeto, podem fazer check-out e check-in dos arquivos que pertencem a esse projeto.

> **Observação:** Você deve habilitar a opção do seu sistema de controle de código-fonte para fazer check-out do mesmo arquivo várias vezes para que vários desenvolvedores trabalhem em um projeto simultaneamente. Para detalhes, consulte a documentação do seu software de controle de código-fonte.
