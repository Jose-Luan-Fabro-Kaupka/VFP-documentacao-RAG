# Comando USE

Abre uma tabela e seus arquivos de índice associados ou abre uma exibição SQL.

```foxpro
USE [[DatabaseName!] TableName | SQLViewName | ?]
   [IN nWorkArea | cTableAlias] [ONLINE] [ADMIN] [AGAIN]
   [NOREQUERY [nDataSessionNumber]] [NODATA]
   [INDEX IndexFileList | ? [ORDER [nIndexNumber | IDXFileName
   | [TAG] TagName [OF CDXFileName] [ASCENDING | DESCENDING]]]]
   [ALIAS cTableAlias] [EXCLUSIVE] [SHARED] [NOUPDATE]
   [CONNSTRING cConnectionString | nStatementHandle ]
```

#### Parâmetros
 **[ DatabaseName !] TableName**
Especifica o nome da tabela a ser aberta. Para abrir uma tabela que não esteja no banco de dados atual, preceda o nome da tabela pelo nome do banco de dados seguido imediatamente por um ponto de exclamação (!). Dica: no Microsoft Windows 98 e posterior, espaços são significativos em nomes de arquivo; portanto, evite espaços extras em TableName e DatabaseName. Se um nome contiver espaços, coloque-o entre aspas (" " ou ' '). Dica: para acessar uma tabela associada ou não a um banco de dados, especifique o caminho completo. Contudo, usar apenas o nome da tabela pode melhorar o desempenho. Observação: se você não incluir o nome de um banco de dados, o Visual FoxPro só poderá abrir tabelas no banco de dados atual. O Visual FoxPro não reconhece corretamente caminhos quando o nome de um disco ou diretório contém ponto de exclamação.
**SQLViewName**
Especifica o nome de uma exibição SQL do banco de dados atual a ser aberta. SQLViewName também pode ser o nome de uma exibição offline criada com a função CREATEOFFLINE( ). Para obter mais informações, consulte Função CREATEOFFLINE( ). Você pode criar uma exibição SQL usando o comando CREATE SQL VIEW.
**?**
Exibe a caixa de diálogo Usar para que você escolha uma tabela.
**IN nWorkArea**
Especifica a área de trabalho em que a tabela será aberta. Para fechar uma tabela em uma área específica, chame USE sem o nome da tabela, mas inclua a cláusula IN e o número da área. A cláusula IN aceita 0, que abre a tabela na menor área de trabalho disponível. Por exemplo, se houver tabelas abertas nas áreas de 1 a 10, `USE customer IN 0` abre customer na área 11.
**IN cTableAlias**
Especifica o alias da tabela a ser aberta na área de trabalho de uma tabela atualmente aberta. O alias da tabela aberta é especificado com cTableAlias. Se nWorkArea e cTableAlias forem omitidos, a tabela será aberta na área de trabalho selecionada no momento.
**ONLINE**
Abre uma exibição offline criada com CREATEOFFLINE( ). Você pode especificar o nome em SQLViewName. Use TABLEUPDATE( ) para atualizar os dados no servidor. A exibição offline deve ser aberta exclusivamente. Antes de abri-la com USE, inclua EXCLUSIVE em USE ou defina SET EXCLUSIVE como ON. Não é possível abrir ou fechar uma exibição offline no modo ONLINE dentro de uma transação.
**ADMIN**
Abre uma exibição offline criada com CREATEOFFLINE( ), mas não atualiza no servidor as alterações feitas nela. ADMIN permite alterar a exibição offline sem atualizar os dados no servidor. Não é possível abrir ou fechar uma exibição offline no modo ADMIN dentro de uma transação.
**AGAIN**
Para abrir uma tabela simultaneamente em várias áreas de trabalho, selecione outra área e emita USE com o nome da tabela e AGAIN, ou emita USE com AGAIN e especifique outra área com IN. Ao abrir novamente uma tabela em outra área, ela assume os atributos da tabela original. Por exemplo, se a tabela original tiver acesso somente leitura ou exclusivo, a nova abertura terá o mesmo acesso. Os arquivos de índice da tabela original ficarão disponíveis para a nova abertura se você não abrir índices novamente. A ordem do índice é definida como 0 nas áreas adicionais. Você pode abrir índices que não foram abertos com a tabela original, o que define a ordem do índice como 0 também para ela. Uma tabela reaberta recebe o alias padrão da área de trabalho. Você pode incluir um alias em cada abertura, desde que sejam exclusivos. No Visual FoxPro para Windows, reabrir uma tabela em outra área não consome outro identificador de arquivo.
**NOREQUERY [ nDataSessionNumber ]**
Especifica que os dados de uma exibição SQL remota não sejam baixados novamente. NOREQUERY está disponível somente para exibições SQL e normalmente é usado ao reabrir uma exibição com AGAIN. Essa cláusula melhora o desempenho de grandes conjuntos de dados. nDataSessionNumber pode especificar que os dados da exibição remota em uma sessão de dados específica não sejam baixados novamente. Se omitido, os dados não serão baixados para a exibição aberta na sessão atual.
**NODATA**
Baixa a estrutura de uma exibição SQL sem os dados. NODATA é o método mais rápido para determinar a estrutura. Observação: abrir uma exibição com NODATA sempre abre um novo cursor. O Visual FoxPro cria uma cláusula WHERE que sempre retorna falso; como nenhum registro atende à condição, nenhuma linha é selecionada e a estrutura é recuperada rapidamente. Dica: NODATA é mais eficiente do que definir a propriedade MaxRecords como 0 por meio de DBSETPROP( ) ou CURSORSETPROP( ), pois MaxRecords ainda exige que a fonte remota crie um cursor com todas as linhas que atendam à cláusula WHERE normal. Para obter mais informações, consulte as funções DBSETPROP( ) e CURSORSETPROP( ).
**INDEX IndexFileList**
Especifica um conjunto de índices a abrir com a tabela. Se a tabela tiver um arquivo de índice composto estrutural, ele será aberto automaticamente. IndexFileList pode conter qualquer combinação de arquivos .idx de entrada única e .cdx compostos. Não é necessário incluir extensões, a menos que arquivos .idx e .cdx tenham o mesmo nome. O primeiro índice da lista é o índice controlador principal, que controla como os registros são acessados e exibidos. Contudo, se o primeiro for um .cdx composto, os registros serão exibidos e acessados na ordem física.
**INDEX ?**
Exibe a caixa de diálogo Abrir com uma lista de arquivos de índice disponíveis.
**ORDER [ nIndexNumber ]**
Especifica um arquivo .idx de entrada única ou uma tag de arquivo .cdx composto como índice controlador principal, diferente do primeiro índice ou tag de IndexFileList. Arquivos .idx são numerados primeiro na ordem da lista; depois vêm as tags do índice composto estrutural e, por fim, as tags dos índices compostos independentes, na ordem de criação. Também é possível usar SET ORDER. Se nIndexNumber for 0, os registros serão exibidos e acessados na ordem física, e os índices permanecerão abertos. ORDER sem nIndexNumber equivale a ORDER 0.
**ORDER [ IDXFileName ]**
Especifica um arquivo de índice .idx de entrada única como índice controlador principal.
**ORDER [TAG TagName ] [OF CDXFileName ]**
Especifica uma tag controladora principal em um arquivo de índice composto .cdx. A tag pode pertencer ao índice composto estrutural ou a qualquer índice composto aberto. Se houver nomes de tag idênticos, inclua OF CDXFileName.
**ASCENDING**
Especifica que os registros sejam acessados e exibidos em ordem crescente.
**DESCENDING**
Especifica que os registros sejam acessados e exibidos em ordem decrescente. ASCENDING ou DESCENDING não altera o arquivo de índice nem a tag; altera somente a ordem de exibição e acesso.
**ALIAS cTableAlias**
Cria um alias para a tabela que pode ser usado com outros comandos e funções. O alias deve começar com uma letra ou sublinhado e pode conter até 254 letras, dígitos ou sublinhados. Observação: o Visual FoxPro cria automaticamente outro alias se o fornecido contiver um caractere não compatível. Ao abrir uma tabela, ela recebe automaticamente um alias igual ao nome da tabela se ALIAS for omitido. Versões anteriores do FoxPro limitavam o alias a 10 caracteres. O Visual FoxPro atribui um alias padrão se houver conflito ou se AGAIN abrir a mesma tabela em várias áreas sem aliases explícitos.
**EXCLUSIVE**
Abre uma tabela para uso exclusivo em uma rede. Para obter mais informações, consulte o comando SET EXCLUSIVE.
**SHARED**
Abre uma tabela para uso compartilhado em uma rede, mesmo quando EXCLUSIVE estiver definido como ON.
**NOUPDATE**
Impede alterações na tabela e em sua estrutura.
**CONNSTRING cConnectionString | nStatementHandle**
Especifica uma cadeia de conexão para a fonte de dados ODBC. cConnectionString pode representar parâmetros normalmente passados a SQLCONNECT( ) ou SQLSTRINGCONNECT( ). nStatementHandle especifica uma variável de memória que representa um identificador de instrução existente de uma conexão existente. Com cConnectionString, o Visual FoxPro passa a cadeia à exibição remota especificada por SQLViewName, que a usa no lugar da cadeia definida anteriormente. Uma cadeia vazia ("") exibe a caixa de diálogo Fonte de Dados ODBC para o usuário selecionar uma fonte. Observação: se os dados da cadeia estiverem incompletos, a fonte exibirá uma caixa de diálogo de logon. Se CONNSTRING for omitido, a exibição remota usará a conexão padrão atual. Consulte a documentação do driver ODBC para obter mais informações. O Visual FoxPro permite substituir a conexão padrão de uma exibição remota e exige nStatementHandle para conexões compartilhadas.

# Observações

Se você emitir USE sem um nome de tabela e houver uma tabela aberta na área de trabalho selecionada, o Visual FoxPro a fechará. Ele também fecha uma tabela quando outra é aberta na mesma área. Não pode haver mais de uma tabela aberta por área de trabalho.

Quando usado com um banco de dados não atual, USE abre o banco automaticamente, mas não o define como atual. Quando a tabela é fechada, o banco permanece aberto.

# Exemplo

O exemplo a seguir abre três tabelas em três áreas de trabalho diferentes. A janela Sessão de Dados é aberta para mostrar onde elas estão abertas e o alias de cada uma.

```foxpro
CLOSE DATABASES
OPEN DATABASE (HOME(2) + 'Data\testdata')
ACTIVATE WINDOW View
USE customer IN 0  && Opens Customer table
USE employee IN 0  && Opens Employee table
USE products IN 0  && Opens Products table
```
