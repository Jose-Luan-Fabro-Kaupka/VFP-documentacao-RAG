# Considerações para criar expressões de índice

Ao criar expressões de índice, observe as seguintes considerações:
 - Se você especificar uma expressão que exceda os limites definidos para a criação de chaves de índice, o Visual FoxPro gera um erro. O comprimento de uma chave de índice em um arquivo de índice composto (.cdx) deve estar entre 1 e 240 caracteres. O comprimento de uma chave de índice em um arquivo de índice (.idx) deve estar entre 1 e 100 caracteres. Com algumas sequências de ordenação ou ao usar caracteres de conjunto de caracteres de byte duplo (DBCS), cada caractere na expressão de índice usa dois caracteres na chave de índice. Nesses casos, o comprimento da expressão de índice é limitado a 120 caracteres.
- Se você criar uma expressão de índice usando campos numéricos, o índice organiza os registros pela soma dos campos, não pelos campos em si.
- O Visual FoxPro não suporta chaves de índice de comprimento variável. Se você tentar construir um índice com uma chave que varia em comprimento, a chave é preenchida com espaços.
- Não use uma variável, um elemento de matriz ou um campo ou expressão de campo de uma tabela em outra área de trabalho para a expressão de índice. Se você acessar um índice que contém uma variável ou campo que não existe mais ou não pode ser localizado, o Visual FoxPro gera uma mensagem de erro.
- Embora o Visual FoxPro gere um erro, é possível criar uma chave de índice com comprimento zero (0). Quando o Visual FoxPro cria um índice, ele avalia os campos no primeiro registro da tabela. Portanto, se a expressão de índice é uma substring de um campo memo vazio, uma chave de índice de comprimento zero é criada. Dica Para evitar criar uma chave de índice de comprimento zero se um campo estiver vazio, pode ser necessário inserir alguns dados temporários no campo do primeiro registro.
- O Visual FoxPro preenche chaves de índice baseadas em campos e expressões Character , Varchar , Varchar (Binary) e Varbinary . Chaves de índice baseadas em campos e expressões Varchar , Varchar (Binary) e Varbinary incluem preenchimento mesmo que esses tipos de dados normalmente não incluam preenchimento. Chaves de índice baseadas em Varchar e Varchar (Binary) são preenchidas com espaços adicionais, semelhante a chaves de índice baseadas em campos e expressões Character . Chaves de índice baseadas em campos ou expressões Varbinary são preenchidas com zeros do lado direito do valor no campo até o comprimento máximo do campo. Por exemplo, os valores 0hAA, 0hAA00 e 0hAA000 têm a mesma chave de índice 0hAA0000. Para obter mais informações, consulte Varchar Field Type e Varbinary Data Type .
- Campos Memo e Blob devem ser combinados com outras expressões de caracteres em expressões de arquivo de índice; não podem ser usados isoladamente. Campos General não podem ser usados em expressões de índice. Se você incluir um campo precedido por um alias de tabela ou letra de área de trabalho na expressão de índice, o Visual FoxPro gera uma mensagem de erro.
- Evite usar campos com alias ao criar índices, mesmo que você possa otimizar cláusulas FOR com a tecnologia Rushmore Query Optimization quando campos com alias são incluídos. Em vários casos, por exemplo, com o comando USE...AGAIN e consultas SQL, um alias diferente é automaticamente atribuído a uma tabela, e o índice pode não ser atualizado ou usado corretamente. Para obter mais informações sobre a tecnologia Rushmore, consulte Using Rushmore Query Optimization to Speed Data Access .
- Embora uma expressão de índice possa conter uma função definida pelo usuário (UDF), não é recomendável incluir uma UDF em uma expressão de índice. Embora tanto procedimentos armazenados quanto funções definidas pelo usuário em uma expressão de índice aumentem o tempo necessário para criar ou atualizar o índice, se sua tabela estiver associada a um banco de dados, você pode preferir usar um procedimento armazenado em vez de uma UDF na expressão de índice. Se você usar uma UDF em uma expressão de índice, o Visual FoxPro deve ser capaz de localizar a função definida pelo usuário. Quando o Visual FoxPro cria um índice, a expressão de índice é salva no arquivo de índice; no entanto, apenas uma referência à UDF é incluída na expressão de índice. A UDF é armazenada em um arquivo separado do banco de dados; portanto, é possível mover ou excluir o arquivo da UDF, o que invalida a referência na expressão de índice à UDF. Em contraste, o código do procedimento armazenado é armazenado no arquivo de tabela (.dbc) e sempre pode ser localizado pelo Visual FoxPro. Além disso, referenciar um procedimento armazenado em uma expressão de índice garante que o índice seja baseado no código exato que você especifica. Além disso, atualizações de índice podem não ocorrer quando funções definidas pelo usuário não estão no escopo de aplicativos que modificam o índice. Se você usar uma UDF na expressão de índice, o Visual FoxPro usa qualquer UDF que esteja no escopo ao indexar a tabela e que tenha o mesmo nome da UDF referenciada no índice. Se você usar uma UDF associada a um banco de dados em uma expressão de índice, o Visual FoxPro trata a expressão da mesma forma que trata expressões de regras e gatilhos que contêm UDFs. Para obter mais informações, consulte Enforcing Business Rules e Trigger Usage .
- Certifique-se de usar funções invariantes em relação à configuração da página de código atual ao criar um índice que deve ser modificado sob diferentes páginas de código atuais. Os resultados de algumas funções usadas em expressões de índice podem variar dependendo da página de código atual. Por exemplo, a função UPPER( ) usa a página de código atual para transformar uma cadeia de caracteres e pode produzir resultados inesperados se o índice for modificado sob diferentes páginas de código atuais ou quando o índice é aplicado a um campo e a página de código atual não é a mesma da página de código associada à tabela. Você pode usar a função STRCONV( ) em vez disso, STRCONV(...,8,...) . O Visual FoxPro avalia expressões de índice lendo dados de caracteres da tabela sem tradução adicional de página de código, mesmo quando a página de código atual (CPCURRENT()) não corresponde à página de código associada à tabela (CPDBF()), para produzir o mesmo índice independentemente da página de código atual.
