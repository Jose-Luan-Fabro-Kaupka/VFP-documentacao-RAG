# Comando EDIT

Exibe campos para edição.

```foxpro
EDIT [FIELDS FieldList] [Scope] [FOR lExpression1] [WHILE lExpression2]
   [FONT cFontName[, nFontSize [, nFontCharSet]]] [STYLE cFontStyle] [FREEZE FieldName]
   [KEY eExpression1[, eExpression2]] [LAST | NOINIT] [LPARTITION]
   [NAME ObjectName] [NOAPPEND] [NOCAPTION] [NODELETE] [NOEDIT | NOMODIFY]
   [NOLINK] [NOMENU] [NOOPTIMIZE] [NORMAL] [NOWAIT]
   [PARTITION nColumnNumber [LEDIT] [REDIT]]
   [PREFERENCE PreferenceName] [REST] [SAVE] [TIMEOUT nSeconds]
   [TITLE cTitleText] [VALID [:F] lExpression3 [ERROR cMessageText]]
   [WHEN lExpression4] [WIDTH nFieldWidth] [WINDOW WindowName1]
   [IN [WINDOW] WindowName2 | IN SCREEN [COLOR SCHEME nSchemeNumber]
```

#### Parâmetros
 **FIELDS FieldList**
Especifica os campos que aparecem na Edit window. Os campos são exibidos na ordem especificada em FieldList. Você pode incluir campos de outras tabelas relacionadas na lista de campos. Quando você inclui um campo de uma tabela relacionada, prefixe o nome do campo com o alias da tabela e um ponto. Se você omitir FIELDS, todos os campos na tabela são exibidos na ordem em que aparecem na estrutura da tabela. A lista de campos pode especificar qualquer combinação de campos ou campos calculados, incluindo campos de tabelas abertas em outras áreas de trabalho. A sintaxe da lista de campos é: FieldName1 [:R] [:nColumnWidth] [:V = lExpression1 [:F] [:E = cMessageText]] [:P = cFormatCodes] [:B = eLowerBound, eUpperBound [:F]] [:H = cHeadingText] [:W = lExpression2] [, FieldName2 [:R]...]

# Campos calculados

A lista de campos pode conter instruções para criar campos calculados. Um campo calculado contém dados somente leitura criados com uma expressão. Esta expressão pode ter qualquer forma, mas deve ser uma expressão Visual FoxPro válida.

A sintaxe da instrução que você usa para criar um campo calculado é:

CalculatedFieldName = eExpression

Este exemplo cria um campo calculado chamado `location`:

```foxpro
CLOSE DATABASES
OPEN DATABASE (HOME(2) + 'data\testdata')
USE customer  && Open customer table
EDIT FIELDS location = ALLTRIM(city) + ', ' + country
```

A lista de campos da cláusula FIELDS inclui oito opções, que permitem tratamento especial de campos exibidos na Edit window.
 **: nColumnWidth**
Especifica o tamanho de exibição de um campo em colunas. O valor de : nColumnWidth não afeta o tamanho do campo na tabela; altera apenas a maneira como o campo aparece na Edit window.
**:R**
No exemplo a seguir, uma Edit window é aberta com os campos cust_id e company. O campo cust_id é somente leitura e não pode ser alterado. CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE customer && Open customer table EDIT FIELDS cust_id:R, company
**:V = lExpression1**
Especifica uma opção de verificação que executa validação de dados em nível de campo dentro da Edit window. Se lExpression1 avalia para true (.T.) quando você move o cursor do campo, os dados inseridos no campo são considerados corretos e o cursor move para o próximo campo. Se lExpression1 avalia para false (.F.), os dados inseridos são considerados incorretos, o cursor permanece no campo e um erro ou exceção é gerado. Se lExpression1 avalia para 0, os dados inseridos são considerados incorretos e o cursor permanece no campo, mas nenhuma mensagem de erro é exibida. Por padrão, lExpression1 é avaliado apenas quando o campo é modificado. Para forçar a verificação, inclua a opção :F. Você pode exibir sua própria mensagem de erro incluindo a opção :E. A opção de verificação não é executada para campos memo.
**:F**
Especifica uma opção de validação forçada que determina se a expressão na opção de verificação ( lExpression1 ) é avaliada quando você move o cursor de um campo ou outra janela é ativada. Se :F não é incluído, lExpression1 é avaliado apenas se alterações são feitas no campo. Se :F é incluído, lExpression1 é avaliado, mesmo se o campo não for modificado.
**:E = cMessageText**
Exibe uma mensagem de erro especificada com cMessageText em vez da mensagem padrão do sistema. Se a expressão de validação :V = lExpression1 avalia para true (.T.), o cursor sai do campo normalmente. Se a expressão avalia para false (.F.), o cursor permanece no campo e a mensagem de erro aparece. Se a expressão de validação :V = lExpression1 avalia para 0, nenhuma mensagem é exibida e o cursor permanece no campo sendo validado. Isso permite exibir suas próprias mensagens de erro em rotinas de validação. A mensagem de erro é exibida apenas se SET NOTIFY estiver ON. O sino é acionado se SET BELL estiver ON. O exemplo a seguir abre a tabela products e exibe os campos product_id e prod_name. Digite um valor maior que 100 no campo product_id para executar a validação do campo. :V especifica os critérios de validação. :F força a verificação de validação a ser executada independentemente de os dados serem alterados ou não. :E substitui a mensagem de erro do sistema Visual FoxPro por uma mensagem de erro definida pelo usuário. No Visual FoxPro, a mensagem de erro é exibida na barra de status na parte inferior da janela principal do Visual FoxPro. Pressione ESC para fechar a Edit window. CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE products && Open products table IF _WINDOWS OR _MAC SET STATUS BAR ON ENDIF USE products EDIT FIELDS in_stock :V = in_stock < 100 ; :F ; :E = 'The stock amount must be less than 100'
**:P = cFormatCodes**
Especifica uma opção picture que permite criar um modelo de edição especificado com cFormatCodes que controla a exibição e entrada de dados para cada campo em uma Edit window. Para obter mais informações sobre o uso de códigos de edição picture, consulte as propriedades Format Property e InputMask Property. O exemplo a seguir usa a opção picture para permitir que apenas dados numéricos em um formato específico sejam inseridos no campo unit_price: CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE products && Open products table EDIT FIELDS unit_price :P = '99,999.99'
**:B = eLowerBound , eUpperBound [:F]**
Especifica um conjunto de limites entre os quais os dados devem estar. As expressões de limite eLowerBound e eUpperBound devem corresponder ao tipo de dados do campo e não podem ser nomes de funções definidas pelo usuário. Se os dados inseridos não estiverem entre eLowerBound e eUpperBound, uma mensagem do sistema é exibida indicando o intervalo entre o qual os dados devem estar. Por padrão, os dados inseridos são verificados contra os valores de limite apenas se você fizer uma alteração no conteúdo do campo. Para forçar a verificação contra os valores de limite, inclua a opção de validação forçada (:F). O exemplo a seguir garante que o valor no campo in_stock esteja entre 1 e 100. Pressione ESC para fechar a Edit window. CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE products && Open products table EDIT FIELDS in_stock :B = 1, 100 :F
**:H = cHeadingText**
Especifica uma opção de cabeçalho (:H) que permite substituir os nomes de campo padrão por seus próprios cabeçalhos, que você especifica com cHeadingText. Por padrão, nomes de campo são colocados à esquerda dos campos na Edit window. O exemplo a seguir fornece cabeçalhos definidos pelo usuário para os campos exibidos. CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE products && Open products table EDIT FIELDS prod_name :H = 'Product Name:', ; unit_price :H = 'Price per Unit:'
**:W = lExpression2**
Especifica uma opção WHEN que permite proibir condicionalmente que o cursor seja movido para um campo baseado no valor da expressão lógica lExpression. (:W) avalia lExpression. Se lExpression2 avalia para false (.F.), você não pode mover o cursor para o campo. Se lExpression2 avalia para true (.T.), você pode mover o cursor para o campo. Funções definidas pelo usuário são suportadas em lExpression2. Mover o cursor para todos os campos é proibido se o campo atual está marcado como somente leitura. Isso ocorre apenas quando cada campo contém uma cláusula WHEN que avalia para false.
**Scope**
Especifica um intervalo de registros que são exibidos na Edit window. As cláusulas de escopo são: ALL, NEXT nRecords, RECORD nRecordNumber e REST. Comandos que incluem Scope operam apenas na tabela na área de trabalho ativa. O escopo padrão para EDIT é ALL registros. Para obter mais informações, consulte o tópico online Scope Clauses.
**FOR lExpression1**
Especifica que apenas os registros que satisfazem a condição lógica lExpression1 são exibidos na Edit window. Usar este argumento permite filtrar registros indesejados. A otimização de consulta Rushmore otimiza uma consulta EDIT FOR se lExpression1 é uma expressão otimizável. Para melhor desempenho, use uma expressão otimizável na cláusula FOR. Para obter mais informações, consulte SET OPTIMIZE Command e Using Rushmore Query Optimization to Speed Data Access.
**WHILE lExpression2**
Especifica uma condição pela qual registros são exibidos na Edit window enquanto a expressão lógica lExpression2 avalia para true (.T.).
**FONT cFontName [, nFontSize [, nFontCharSet ]]**
Especifica a fonte e o tamanho da fonte da Edit window. A expressão de caractere cFontName especifica o nome da fonte, e a expressão numérica nFontSize especifica o tamanho da fonte. Você pode especificar um script de idioma com nFontCharSet. Consulte a função GETFONT( ) para uma lista de valores de script de idioma disponíveis. Por exemplo, a cláusula a seguir especifica fonte Courier de 16 pontos para os campos exibidos em uma Edit window: FONT 'Courier',16 Se você incluir a cláusula FONT mas omitir o tamanho da fonte nFontSize, uma fonte de 10 pontos é usada na Edit window. Se você omitir a cláusula FONT, MS Sans Serif de 8 pontos é usada. Se a fonte que você especificar não estiver disponível, uma fonte com características de fonte semelhantes é substituída.
**STYLE cFontStyle**
Especifica o estilo de fonte da Edit window no Visual FoxPro. Se você omitir a cláusula STYLE, o estilo de fonte Normal é usado. Se o estilo de fonte que você especificar não estiver disponível, um estilo de fonte com características semelhantes é substituído. Caractere Estilo de fonte B Bold I Italic N Normal O Outline Q Opaque S Shadow - Strikeout T Transparent U Underline Você pode incluir mais de um caractere para especificar uma combinação de estilos de fonte. O exemplo a seguir abre uma Edit window e usa uma fonte sublinhada: CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE customer && Opens customer table IF _WINDOWS EDIT FIELDS contact FONT 'System', 15 STYLE 'NU' ENDIF IF _MAC EDIT FIELDS contact FONT 'Geneva', 14 STYLE 'NU' ENDIF
**FREEZE FieldName**
Permite que alterações sejam feitas em apenas um campo especificado com FieldName na Edit window. Os campos restantes são exibidos e não podem ser editados.
**KEY eExpression1 [, eExpression2 ]**
Limita o escopo dos registros que são exibidos na Edit window. Com KEY, você pode especificar um valor de chave de índice ( eExpression1 ) ou um intervalo de valores de chave ( eExpression1, eExpression2 ) para os registros exibidos na Edit window. A tabela deve estar indexada, e o valor ou valores de chave de índice incluídos na cláusula KEY devem ser do mesmo tipo de dados que a expressão de índice do arquivo de índice mestre ou tag mestre. No exemplo a seguir, apenas registros com códigos postais no intervalo de 10.000 a 30.000 são exibidos na Edit window: CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE customer && Open customer table SET ORDER TO postalcode EDIT KEY '10000', '30000'
**LAST | NOINIT**
Salva quaisquer alterações de configuração feitas na aparência de uma Edit window. As alterações são salvas no arquivo FoxUser.dbf e podem incluir alterações na lista de campos, no tamanho de cada campo e na localização e tamanho da Edit window. Para obter mais informações sobre este arquivo, consulte SET RESOURCE Command. Se você emitir EDIT com a cláusula LAST, a Edit window abre na mesma configuração que foi salva pela última vez no arquivo FoxUser.dbf. Isso restaura a configuração anterior da Edit window criada com o último EDIT. Se o último comando EDIT emitido na Command window incluiu uma longa lista de cláusulas, emita EDIT LAST para evitar ter que redigitar o comando. Quaisquer alterações de configuração da Edit window que você fizer na sessão atual não são salvas se você sair do EDIT pressionando CTRL+Q.
**LPARTITION**
Coloca o cursor no primeiro campo na partição esquerda da Edit window. Uma Edit window pode ser dividida em partições esquerda e direita incluindo a cláusula PARTITION. Por padrão, o cursor é colocado no primeiro campo na partição direita quando a Edit window é aberta. O cursor é colocado na partição direita da Edit window se você incluir LPARTITION sem a cláusula PARTITION.
**NAME ObjectName**
Cria uma referência de objeto para a Edit window, permitindo manipular a Edit window com propriedades orientadas a objetos disponíveis para o controle Grid. Para informações adicionais sobre programação orientada a objetos no Visual FoxPro, consulte Object-Oriented Programming. Para informações adicionais sobre as propriedades do controle Grid que você pode especificar para uma Edit window criada com a cláusula NAME, consulte o tópico Grid Control.
**NOAPPEND**
Impede que o usuário adicione registros à tabela pressionando CTRL+Y ou escolhendo Append Mode no menu View. Observação Incluir NOAPPEND não impede que você acrescente um registro de dentro de uma rotina (criada com VALID, WHEN ou ON KEY LABEL) enquanto estiver na Edit window.
**NOCAPTION**
Especifica usar sempre o nome do campo de uma tabela ou view para os cabeçalhos de coluna, mesmo quando o banco de dados contém um caption amigável para a tabela. Esta cláusula se aplica apenas a tabelas ou views em um banco de dados.
**NODELETE**
Impede que registros sejam marcados para exclusão de dentro de uma Edit window. Por padrão, um registro pode ser marcado para exclusão pressionando CTRL+T, escolhendo Toggle Deletion Mark no menu Table ou clicando na coluna mais à esquerda do registro a ser excluído. Observação Incluir NODELETE não impede que você marque um registro para exclusão de dentro de uma rotina (criada com VALID, WHEN ou ON KEY LABEL) enquanto estiver na Edit window.
**NOEDIT | NOMODIFY**
Impede que um usuário modifique a tabela. NOEDIT e NOMODIFY são idênticos. Se você incluir qualquer cláusula, pode navegar ou pesquisar a tabela, mas não pode editá-la. No entanto, você pode acrescentar e excluir registros.
**NOLINK**
Desvincula partições na Edit window. Por padrão, as partições esquerda e direita da Edit window estão vinculadas; quando você rola por uma partição, a outra partição rola.
**NOMENU**
Remove o título do menu Table no Visual FoxPro da barra de menu do sistema, impedindo o acesso ao menu Edit.
**NOOPTIMIZE**
Desabilita a otimização de consulta Rushmore de EDIT. Para obter mais informações, consulte SET OPTIMIZE Command e Using Rushmore Query Optimization to Speed Data Access.
**NORMAL**
Abre a Edit window com suas configurações padrão normais, como suas cores, tamanho, posição, título e opções de controle (GROW, FLOAT, ZOOM e assim por diante). Se você omitir NORMAL e a janela de saída atual é uma janela definida pelo usuário com suas próprias configurações, a Edit window assume essas configurações definidas pelo usuário também.
**NOWAIT**
Continua a execução do programa imediatamente depois que a Edit window é aberta. O programa não espera que a Edit window seja fechada, mas continua executando na linha do programa imediatamente após a linha do programa contendo EDIT NOWAIT. Se você omitir NOWAIT, quando EDIT é emitido de dentro de um programa, uma Edit window é aberta e a execução do programa pausa até que a Edit window seja fechada. NOWAIT está disponível apenas de dentro de um programa. Incluir NOWAIT ao emitir EDIT da Command window não tem efeito.
**PARTITION nColumnNumber**
Divide uma Edit window em partições esquerda e direita com nColumnNumber especificando o número da coluna da barra de divisão. Por exemplo, se nColumnNumber é 20, a barra de divisão é colocada na coluna 20 da Edit window.
**LEDIT**
Especifica que a partição esquerda da Edit window aparece no modo Browse.
**REDIT**
Especifica que a partição direita da Edit window aparece no modo Browse. O exemplo a seguir abre uma Edit window com a barra de divisão colocada na coluna 20 e a partição direita aberta no modo Browse. Inclua ambas as palavras-chave para abrir ambas as partições no modo Browse. CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE customer && Opens customer table EDIT PARTITION 30 REDIT
**PREFERENCE PreferenceName**
Salva os atributos e opções de uma Edit window para uso posterior. Diferente de LAST, que restaura a Edit window como apareceu na sessão anterior, PREFERENCE salva os atributos de uma Edit window indefinidamente no arquivo de recursos FoxUser.dbf. Preferências podem ser recuperadas a qualquer momento. Para obter mais informações sobre o arquivo de recursos FoxUser.dbf, consulte SET RESOURCE Command. Emitir EDIT com o nome de preferência PreferenceName especificado pela primeira vez cria uma entrada no arquivo FoxUser.dbf que salva a configuração da Edit window. Emitir EDIT posteriormente com o mesmo nome de preferência restaura a Edit window para esse estado de preferência. Quando a Edit window é fechada, o estado de preferência é atualizado. Nomes de preferência podem ter até 10 caracteres, devem começar com uma letra ou sublinhado, e podem conter qualquer combinação de letras, números e sublinhados. Depois de ter uma preferência como deseja, você pode impedir que seja alterada. Feche a Edit window, emita SET RESOURCE OFF, abra o arquivo FoxUser.dbf como uma tabela e altere o campo contendo a preferência para somente leitura alterando o valor do campo lógico READONLY para true (.T.). Para obter mais informações sobre o arquivo de recursos FoxUser.dbf, consulte SET RESOURCE Command.
**REST**
Impede que o ponteiro de registro seja movido de sua posição atual para o topo da tabela. Por padrão, EDIT posiciona o ponteiro de registro no topo da tabela.
**SAVE**
Mantém a Edit window e quaisquer de suas janelas de edição de texto de campo memo ativas e visíveis (abertas). Você pode então retornar à Edit window depois de percorrer outras janelas abertas com o teclado ou o mouse. SAVE está disponível apenas de dentro de um programa. SAVE não tem efeito quando incluído com EDIT na Command window porque EDIT SAVE é sempre o padrão no modo interativo.
**TIMEOUT nSeconds**
Especifica quanto tempo uma Edit window espera por entrada. A expressão numérica nSeconds especifica quantos segundos podem passar sem qualquer entrada antes que a Edit window feche automaticamente. TIMEOUT está disponível apenas de dentro de um programa; não tem efeito quando você emite EDIT da Command window. No exemplo a seguir, a Edit window é fechada se nenhuma entrada ocorrer em 10 segundos. DEFINE WINDOW wEdit FROM 1,1 TO 24,40 ; CLOSE ; GROW ; COLOR SCHEME 10 CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE customer && Open customer table EDIT WINDOW wEdit ; FIELDS phone :H = 'Phone Number:' , ; company :H = 'Company:' ; TIMEOUT 10 RELEASE WINDOW wEdit
**TITLE cTitleText**
Substitui o nome ou alias padrão da tabela que aparece na barra de título da Edit window pelo título que você especifica com cTitleText. Caso contrário, o nome ou alias da tabela sendo navegada aparece na barra de título. Se você emitir EDIT WINDOW para colocar a Edit window em uma janela definida pelo usuário, o título da Edit window substitui o título da janela definida pelo usuário. CLOSE DATABASES OPEN DATABASE (HOME(2) + 'data\testdata') USE customer && Open customer table EDIT; TITLE 'My Edit Window' ; FIELDS phone :H = 'Phone Number' , ; company :H = 'Company:'
**VALID lExpression3**
Executa validação em nível de registro em uma Edit window. A cláusula VALID é executada apenas se uma alteração é feita no registro e você move o cursor para outro registro. A cláusula VALID não é executada se a única alteração é em um campo memo. Se VALID retorna true (.T.), você pode mover o cursor para outro registro. Se VALID retorna false (.F.), o cursor permanece no campo atual e o Visual FoxPro exibe uma mensagem de erro. Você pode exibir sua própria mensagem de erro quando VALID retorna false incluindo a cláusula ERROR. A expressão de caractere cMessageText é exibida como a mensagem de erro. Se VALID retorna 0, o cursor permanece no campo atual e uma mensagem de erro não é exibida. A cláusula VALID não deve ser confundida com a opção de verificação (:V), que habilita validação em nível de campo.
**:F**
Força a cláusula VALID a executar antes que o usuário mova o cursor para o próximo registro. Neste caso, VALID é executado mesmo se o registro não for alterado.
**ERROR cMessageText**
Especifica uma mensagem de erro que substitui o padrão do sistema e cujo conteúdo você define com cMessageText. O Visual FoxPro exibe sua mensagem de erro quando VALID retorna false (.F.).
**WHEN lExpression4**
Avalia uma condição quando o usuário move o cursor para outro registro. Se lExpression4 avalia para true (.T.), o usuário pode modificar o registro para o qual se moveu. Se lExpression4 avalia para false (.F.) ou 0, o registro para o qual o usuário se move torna-se somente leitura e não pode ser modificado. A cláusula WHEN não é executada quando outra janela é ativada.
**WIDTH nFieldWidth**
Limita o número de caracteres exibidos para todos os campos em uma partição da Edit window a nFieldWidth. Incluir a cláusula WIDTH não altera o tamanho dos campos na tabela em si; altera apenas a maneira como os campos são exibidos na Edit window. Se uma largura foi especificada para um campo individual com a cláusula FIELDS, ela substitui a largura especificada com a cláusula WIDTH para esse campo.
**WINDOW WindowName1**
Especifica uma janela definida pelo usuário cujas características a Edit window assume. Por exemplo, se a janela definida pelo usuário é criada com a cláusula FLOAT, a Edit window pode ser movida. A janela especificada não precisa estar ativa ou visível, mas deve ser definida.
**IN [WINDOW] WindowName2**
Especifica a janela pai dentro da qual a Edit window é aberta. A Edit window não assume as características da janela pai. Uma Edit window ativada dentro de uma janela pai não pode ser movida para fora da janela pai. Se a janela pai é movida, a Edit window se move com ela. Para acessar a Edit window, a janela pai deve primeiro ser definida com DEFINE WINDOW e deve estar ativa e visível.
**IN SCREEN**
Coloca explicitamente uma Edit window na janela principal do Visual FoxPro quando uma janela definida pelo usuário está ativa.
**COLOR SCHEME nSchemeNumber**
Especifica o número de um esquema de cores usado para as cores da Edit window. No Visual FoxPro, a Edit window assume o esquema de cores estabelecido usando o Color Control Panel.

# Observações

EDIT permite editar a tabela selecionada dentro de uma janela. EDIT se comporta de forma idêntica a CHANGE.

Se você pressionar ESC para sair da Edit window, as alterações feitas no último campo que você modificou são descartadas. No entanto, se você mover para outro registro depois de modificar um campo, suas alterações no campo são salvas.

Em um programa, use DEACTIVATE WINDOW para salvar suas alterações e fechar uma Edit window. Inclua o nome da Edit window em DEACTIVATE WINDOW. Para obter mais informações sobre nomes de Edit window, consulte WTITLE( ) Function.

# Suporte a SET SKIP

SET SKIP permite estabelecer um relacionamento um-para-muitos entre duas tabelas (consulte o exemplo). Para cada registro na tabela pai, pode haver múltiplos registros relacionados na tabela filha. Se você criar um relacionamento um-para-muitos, pode usar EDIT para visualizar registros de ambas as tabelas pai e filha.

O registro pai aparece uma vez, junto com o primeiro registro correspondente da tabela filha. Quaisquer registros correspondentes subsequentes são exibidos nas linhas seguintes ao registro pai e ao primeiro registro filho correspondente. No FoxPro para MS-DOS, blocos sombreados são exibidos em qualquer coluna contendo informações da tabela pai além do primeiro registro correspondente. No Visual FoxPro, o caractere de preenchimento para informações repetidas do pai depende da fonte atual da Edit window.

Para obter mais informações, consulte SET SKIP Command.

# Suporte a COL( ) e ROW( )

Use COL( ) e ROW( ) para retornar a posição atual de linha e coluna na tela do cursor em uma Edit window. Se uma Edit window é aberta na janela principal do Visual FoxPro, a posição do cursor retornada é relativa à janela principal do Visual FoxPro, não à Edit window em si. Se uma Edit window é aberta em uma janela definida pelo usuário, COL( ) e ROW( ) retornam a posição do cursor relativa à janela definida pelo usuário.

# Exemplo

O exemplo a seguir usa SET SKIP para criar um relacionamento um-para-muitos entre duas tabelas. Há um único registro na tabela pai (`customer`) para cada fatura criada. A tabela filha (`orders`) contém múltiplos registros para cada registro na tabela pai.

Depois que o relacionamento é criado, uma Edit window exibindo registros de ambas as tabelas pai e filha é aberta.

```foxpro
CLEAR
CLOSE DATABASES
OPEN DATABASE (HOME(2) + 'data\testdata')
USE customer ORDER cust_id IN 0   && Parent table
USE orders ORDER cust_id IN 0  && Child table
SELECT customer     && Back to parent work area
SET RELATION TO cust_id INTO orders     && Establish relationship
SET SKIP TO orders  && One-to-many relationship
WAIT WINDOW 'Scroll to see shipping dates for each customer' NOWAIT
```
