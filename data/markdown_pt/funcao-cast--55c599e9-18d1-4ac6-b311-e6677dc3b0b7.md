# Função CAST( )

Converte uma expressão de um tipo de dados para outro.

```foxpro
CAST(eExpression AS cDataType [(nFieldWidth [, nPrecision])]
   [NULL | NOT NULL])
```

#### Parâmetros
 **eExpression**
Especifica uma expressão de dados, geralmente em uma instrução SQL, que você deseja converter para outro tipo de dados. eExpression pode ser um campo, campo calculado ou outro tipo de expressão.
**cDataType**
Especifica o nome válido ou a letra que representa o nome do tipo de dados de destino. cDataType também pode ser uma expressão que avalia para um nome de tipo de dados válido ou uma letra que representa um tipo de dados válido. Observação Se você especificar uma expressão para cDataType , deve colocar a expressão especificada para cDataType entre parênteses. Alguns tipos de dados de campo exigem que você especifique um valor para nFieldWidth , nPrecision ou ambos. A tabela a seguir lista os valores de cDataType e se nFieldWidth e nPrecision se aplicam. cDataType Tipo de dados nFieldWidth nPrecision W, Blob Blob Não Não C, Char, Character Character Sim Não Y, Currency Currency Não Não D, Date Date Não Não T, DateTime DateTime Não Não B, Double Double Não Sim F, Float Floating Sim Sim G, General General Não Não I, Int, Integer Integer Não Não L, Logical Logical Não Não M, Memo Memo Não Não N, Num, Numeric Numeric Sim Sim Q, Varbinary Varbinary Sim Não V, Varchar Varchar Sim Não
**nFieldWidth**
Especifica a largura do campo para determinados tipos de dados. O Visual FoxPro ignora nFieldWidth para os seguintes tipos de dados: D, T, I, Y, L, M, G e W. Se nFieldWidth não for especificado, são usados valores padrão, por exemplo, conforme definido pelo comando CREATE TABLE.
**nPrecision**
Especifica o número de casas decimais de precisão para determinados tipos de dados. O Visual FoxPro ignora nPrecision para os seguintes tipos de dados: C, D, T, I, Y, L, M, G, V, Q e W. Se nPrecision não for incluído para o tipo de dados Numeric ou Float, o padrão é zero (0), ou seja, sem casas decimais. Se nPrecision não for incluído para o tipo de dados Double, nPrecision assume por padrão o número de casas decimais de precisão definido pelo comando SET DECIMALS. Se nPrecision não for especificado para qualquer outro tipo de dados, são usados valores padrão, por exemplo, conforme definido pelo comando CREATE TABLE.
**NULL | NOT NULL**
Especifica se valores nulos são permitidos no campo. Observação Se um ou mais campos podem conter valores nulos, o número máximo de campos que a tabela pode conter é reduzido de 255 para 254. Se NULL ou NOT NULL não for especificado, é herdado da expressão.

Se você especificar precisão decimal, conversões entre tipos de dados numéricos, por exemplo, Numeric, Float, Currency e Double, para o tipo de dados Integer podem resultar em perda de precisão.

Para conversões para os tipos de dados Character, Varchar e Varbinary, se a largura do campo especificada for menor que a dos dados originais, o Visual FoxPro trunca os valores para caber na largura do campo. Para conversões para o tipo de dados Character, se a largura especificada for maior que a dos dados originais, o Visual FoxPro preenche o campo com espaços à direita do valor.

# Exemplo

O exemplo a seguir usa o comando SQL SELECT para recuperar dados do campo Product_ID na tabela Products do banco de dados de exemplo do Visual FoxPro, TestData.dbc. O exemplo usa a função CAST( ) para converter os resultados retornados da expressão unit_Cost * in_Stock, que têm tipo Currency, como um valor com tipo Numeric com largura de campo 8 e precisão decimal 2.

```foxpro
CLEAR ALL
OPEN DATABASE HOME(2) + 'Data\Testdata.dbc'
SELECT Product_ID, CAST(unit_Cost * in_Stock AS Numeric(8,2)) FROM Products
```
