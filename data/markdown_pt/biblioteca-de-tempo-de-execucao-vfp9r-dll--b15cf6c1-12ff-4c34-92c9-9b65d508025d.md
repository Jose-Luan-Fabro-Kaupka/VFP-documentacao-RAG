# Biblioteca de tempo de execução VFP9R.DLL

A biblioteca de tempo de execução do Visual FoxPro VFP9R.dll é a principal biblioteca de tempo de execução usada pela maioria dos aplicativos Visual FoxPro e fornece serviços para os seguintes tipos de aplicativo Visual FoxPro:
 - Arquivos de aplicativo distribuído (.exe)
- Arquivos de servidor Automation fora de processo (.exe)
- Arquivos de servidor Automation em processo (.dll)

Esta biblioteca de tempo de execução está localizada no diretório ..\Program Files\Common Files\Microsoft Shared\VFP.

A principal biblioteca de tempo de execução do Visual FoxPro não é compartilhada por todos os servidores Automation em processo (.dll) múltiplos. Em vez disso, cada servidor Automation em processo usa uma instância separada da principal biblioteca de tempo de execução do Visual FoxPro. As regras a seguir determinam como os servidores Automation em processo usam a principal biblioteca de tempo de execução do Visual FoxPro:
 - O arquivo .dll em processo que é chamado primeiro tem uso exclusivo da principal biblioteca de tempo de execução do Visual FoxPro. Se um arquivo .dll em processo já tem uso exclusivo da principal biblioteca de tempo de execução do Visual FoxPro, uma cópia renomeada da principal biblioteca de tempo de execução do Visual FoxPro é criada em disco e carregada na memória para cada .dll em processo chamado. A principal biblioteca de tempo de execução do Visual FoxPro recebe um nome baseado no nome do .dll em processo. Por exemplo, suponha que você chame um .dll em processo chamado MyServer.dll. Uma cópia da biblioteca de tempo de execução do Visual FoxPro é renomeada para MyServerR.dll e carregada na memória para atender o .dll em processo. Isso também pode ocorrer com um servidor .exe do Visual FoxPro criando uma instância de um servidor .dll, uma situação em que ambos compartilham a mesma biblioteca de tempo de execução do mesmo processo.
- As bibliotecas de tempo de execução do Visual FoxPro são renomeadas apenas para .dlls em processo que são executados no mesmo processo. Isso significa que dois clientes separados, cada um executando em seu próprio processo, podem carregar dois arquivos .dll em processo do Visual FoxPro diferentes sem que o tempo de execução seja renomeado. Neste caso, ambos os arquivos .dll em processo do Visual FoxPro usam a principal biblioteca de tempo de execução do Visual FoxPro porque os clientes carregam em processos separados.
- Vários servidores Automation, criados com a cláusula OLEPUBLIC no comando DEFINE CLASS, em um único .dll em processo compartilham a mesma principal biblioteca de tempo de execução do Visual FoxPro. Neste caso, é possível que os servidores Automation possam afetar uns aos outros compartilhando variáveis de memória PUBLIC, definindo os mesmos comandos SET e assim por diante se residirem em um thread comum. Tenha cuidado para que vários servidores Automation em um único .dll em processo não interfiram uns nos outros. A nova classe Session pode ajudar a eliminar alguns desses conflitos. Usar a biblioteca de tempo de execução multithread do Visual FoxPro, VFP9T.dll, evita esses conflitos porque objetos criados em threads separados usarão seu próprio espaço de memória separado (armazenamento local de thread).

Você pode usar a principal biblioteca de tempo de execução do Visual FoxPro com servidores .dll em processo. Como há limitações no uso da principal biblioteca de tempo de execução do Visual FoxPro, você deve considerar usar a biblioteca de tempo de execução multithread do Visual FoxPro, VFPVersionNumberT.dll. A principal biblioteca de tempo de execução do Visual FoxPro não protege totalmente dados de instância e valores globais; portanto, a biblioteca bloqueia vários objetos de executar código simultaneamente. Se um dos objetos está executando código, todas as outras instâncias devem entrar na fila para executar código. Quando o objeto que está executando código termina, outro objeto pode entrar no tempo de execução para iniciar sua execução, seja uma atribuição de propriedade ou invocação de método. Embora isso possa não ser ideal em muitos cenários de aplicativo, existem certos tipos de aplicativos de servidor em que essa pode ser a abordagem ideal.

Se servidores .dll em processo são implantados em um pacote Component Services (ou Microsoft Transaction Server), criar uma instância do servidor carregará o .dll no espaço de memória de um processo Component Services em vez do processo chamador. Além disso, arquivos .exe de vários processos podem instanciar servidores .dll do Visual FoxPro que serão carregados em um único processo Component Services. Component Services gera ou reutiliza um thread para cada cliente que solicita uma instância (OLEPUBLIC) de um servidor Visual FoxPro. Como esses aplicativos frequentemente requerem escalabilidade empresarial, há o potencial de muitas instâncias simultâneas acessarem seu servidor Visual FoxPro. Se apenas um cliente (instância) pode executar código por vez, todos os outros devem esperar. Com uma máquina de processador único, isso pode ser adequado, dependendo da natureza e dos tempos de execução dos métodos no seu servidor. Lembre-se, um processador único pode executar apenas uma linha de código por vez.

> **Dica:** Você deve sempre considerar usar a biblioteca de tempo de execução multithread do Visual FoxPro para máquinas com vários processadores, já que cada processador pode executar código simultaneamente para objetos diferentes. Como o comportamento de bloqueio da principal biblioteca de tempo de execução do Visual FoxPro impede a execução simultânea de código, você deve usar a biblioteca de tempo de execução multithread do Visual FoxPro para a maioria das situações.
