# Função RLOCK( )

Tenta bloquear um registro ou registros de tabela.

```foxpro
RLOCK([nWorkArea | cTableAlias] | [cRecordNumberList, nWorkArea
 | cTableAlias])
```

#### Parâmetros
 **nWorkArea | cTableAlias**
Especifica o número da área de trabalho ou o alias da tabela para uma tabela aberta em outra área de trabalho. Se você não especificar uma área de trabalho ou alias, RLOCK( ) tenta bloquear o registro atual na tabela na área de trabalho atualmente selecionada.
**cRecordNumberList**
Especifica que RLOCK( ) tenta bloquear vários registros. A expressão de caracteres cRecordNumberList especifica um ou mais números de registro, separados por vírgulas, que RLOCK( ) tenta bloquear. Por exemplo, para tentar bloqueios de registro nos quatro primeiros registros de uma tabela, cRecordNumberList deve conter 1, 2, 3, 4. Para bloquear vários registros, você deve ter SET MULTILOCKS ativado e deve incluir o número da área de trabalho ( nWorkArea ) ou o alias ( cTableAlias ) da tabela na qual você tenta bloquear vários registros. Você também pode bloquear vários registros movendo o ponteiro de registro para o registro que deseja bloquear, emitindo RLOCK( ) ou LOCK( ) e repetindo esse processo para registros adicionais. No Visual FoxPro, você pode especificar 0 como número de registro. Especificar 0 permite tentar bloquear o cabeçalho da tabela. Cuidado Mantenha o cabeçalho da tabela bloqueado pelo menor tempo possível, pois outros usuários não podem adicionar registros à tabela quando o cabeçalho da tabela está bloqueado. Libere o bloqueio do cabeçalho da tabela com UNLOCK RECORD 0, UNLOCK ou UNLOCK ALL. Se todos os registros especificados em cRecordNumberList são bloqueados com sucesso, RLOCK( ) retorna true (.T.). Se um ou mais dos registros especificados em cRecordNumberList não podem ser bloqueados, RLOCK( ) retorna false (.F.) e não bloqueia nenhum dos registros. Em ambos os casos, bloqueios de registro existentes permanecem em vigor. O bloqueio de vários registros é um processo aditivo — colocar bloqueios de registro adicionais não libera bloqueios de registro existentes. Do ponto de vista de desempenho, é sempre mais rápido bloquear a tabela inteira do que bloquear mesmo um pequeno número de registros.

# Observações

RLOCK( ) é idêntico a LOCK( ).

Alterações em registros bloqueados explicitamente não são salvas até que o registro seja desbloqueado ou o ponteiro de registro seja movido.

Se o bloqueio ou bloqueios são colocados com sucesso, RLOCK( ) retorna true (.T.). Registros bloqueados estão disponíveis para acesso de leitura e gravação pelo usuário que colocou os bloqueios e para acesso somente leitura por todos os outros usuários na rede.

Executar RLOCK( ) não garante que a tentativa de bloqueio de registro ou bloqueios seja bem-sucedida. Um bloqueio de registro não pode ser colocado em um registro já bloqueado por outro usuário ou em uma tabela bloqueada por outro usuário. Se o bloqueio de registro ou bloqueios não podem ser colocados por qualquer motivo, RLOCK( ) retorna false (.F.).

Por padrão, RLOCK( ) faz uma tentativa de bloquear um registro. Use SET REPROCESS para tentar novamente automaticamente um bloqueio de registro quando a primeira tentativa falhar. SET REPROCESS controla o número de tentativas de bloqueio ou o tempo durante o qual as tentativas de bloqueio são feitas quando a tentativa inicial de bloqueio é malsucedida. Para obter mais informações sobre SET REPROCESS e bloqueio de tabela, consulte o comando SET REPROCESS.

SET MULTILOCKS determina se você pode bloquear vários registros em uma tabela. Se SET MULTILOCKS estiver desativado (o padrão), você pode bloquear somente um único registro em uma tabela. Se SET MULTILOCKS estiver ativado, você pode bloquear vários registros em uma tabela. Para obter mais informações, consulte o comando SET MULTILOCKS.

Um registro de tabela pode ser desbloqueado somente pelo usuário que colocou o bloqueio. Bloqueios de registro podem ser liberados emitindo UNLOCK, fechando a tabela ou saindo do Visual FoxPro.

UNLOCK pode ser usado para liberar bloqueios de registro na área de trabalho atual, em uma área de trabalho específica ou em todas as áreas de trabalho. Para obter mais informações, consulte o comando UNLOCK.

Alternar SET MULTILOCKS de ON para OFF ou de OFF para ON executa implicitamente UNLOCK ALL. Todos os bloqueios de registro em todas as áreas de trabalho são liberados.

Para fechar tabelas, use USE, CLEAR ALL ou CLOSE DATABASES.

Para obter mais informações sobre bloqueio de registro e arquivo e compartilhamento de tabelas em uma rede, consulte Programming for Shared Access.

# Exemplo

O exemplo a seguir bloqueia e desbloqueia os quatro primeiros registros nas tabelas `customer` e `employee`.

```foxpro
CLOSE DATABASES
OPEN DATABASE (HOME(2) + 'Data\testdata')
SET REPROCESS TO 3 AUTOMATIC
STORE '1,2,3,4' TO gcRecList
gcOldExc = SET('EXCLUSIVE')
SET EXCLUSIVE OFF
SELECT 0
USE employee  && Open Employee table
SELECT 0
USE customer  && Open Customer table
? LOCK('1,2,3,4', 'customer')  && Lock 1st 4 records in customer
? RLOCK(gcRecList, 'employee')  && Lock 1st 4 records in employee
UNLOCK IN customer
UNLOCK IN employee
SET EXCLUSIVE &gcOldExc
```
