# Comando PROCEDURE

Cria um procedimento definido pelo usuário em um arquivo de programa. Há duas versões da sintaxe.

```foxpro
PROCEDURE ProcedureName
   [ LPARAMETERS parameter1 [ ,parameter2 ] ,... ]
      Commands
   [ RETURN [ eExpression ] ]
[ENDPROC]
```

```foxpro
PROCEDURE ProcedureName( [ parameter1 [ AS para1type ][ ,parameter2
[AS para2type ] ] ,...] ) [ AS returntype ]
      Commands
   [ RETURN [ eExpression ] ]
[ENDPROC]
```

#### Parâmetros
 **PROCEDURE ProcedureName**
Designa o início de um procedimento definido pelo usuário e especifica o nome do procedimento. ProcedureName deve começar com uma letra ou sublinhado e pode conter até 254 caracteres com qualquer combinação de letras, números e sublinhados.
**[ LPARAMETERS parameter1 [ , parameter2 ] ,... ] ]**
Atribui dados do programa chamador a variáveis ou matrizes locais. Você também pode usar a palavra-chave PARAMETERS em vez de LPARAMETERS para aceitar parâmetros com escopo privado. Você pode passar no máximo 26 parâmetros para um procedimento. Para obter mais informações, consulte Comando LPARAMETERS e Comando PARAMETERS.
**( [ parameter1 [ AS para1type ][ , parameter2 [ AS para2type ] ],...] )**
Atribui dados do programa chamador a variáveis ou matrizes locais. Você pode usar a cláusula AS para1type para especificar o tipo de dados da variável. Observação Incluir os parâmetros entre parênteses (()) imediatamente após o nome do procedimento indica que os parâmetros têm escopo local para o procedimento.
**[ AS returntype ]**
Especifica o tipo de dados do valor de retorno. Você pode usar a cláusula AS para implementar tipagem forte. Para obter mais informações, consulte Como: implementar tipagem forte para código de classe, objeto e variável.
**Commands**
Especifica os comandos do Visual FoxPro a serem executados ao executar a função.
**[ RETURN [ eExpression ] ]**
Retorna o controle ao programa chamador ou a outro programa. eExpression pode especificar um valor de retorno. Observação Você pode incluir o comando RETURN em qualquer lugar do procedimento para retornar o controle ao programa chamador ou a outro programa e para definir um valor retornado pelo procedimento. Se você não incluir o comando RETURN, o Visual FoxPro executa um RETURN implícito automaticamente quando o procedimento termina. Se o comando RETURN não incluir um valor de retorno ou se um RETURN implícito for executado, o Visual FoxPro atribui True (.T.) como valor de retorno. Para obter mais informações, consulte Comando RETURN.
**[ ENDPROC ]**
Indica o fim da estrutura PROCEDURE. Observação A palavra-chave ENDPROC é opcional porque a função termina quando encontra outro comando PROCEDURE, um comando FUNCTION ou o fim do arquivo de programa. Você não pode incluir código de programa executável normal após procedimentos definidos pelo usuário em um arquivo de programa. Somente outros procedimentos definidos pelo usuário, funções e definições de classe podem seguir o primeiro comando PROCEDURE ou FUNCTION no arquivo.

# Observações

Por padrão, os parâmetros são passados aos procedimentos por valor. Para obter informações sobre como passar parâmetros aos procedimentos por referência, consulte Comando SET UDFPARMS.

Quando você emite o comando DO com um nome de procedimento, o Visual FoxPro pesquisa o procedimento na seguinte ordem:
 - O arquivo que contém o comando DO.
- O banco de dados atual.
- Arquivos de procedimento abertos com SET PROCEDURE. Para obter mais informações, consulte Comando SET PROCEDURE.
- Arquivos de programa na cadeia de execução. O Visual FoxPro pesquisa arquivos de programa na ordem do programa executado mais recentemente ao primeiro programa executado.
- Um arquivo de programa autônomo.

Se um arquivo de programa correspondente for encontrado, o Visual FoxPro executa o programa. Caso contrário, o Visual FoxPro gera uma mensagem de erro.

Para executar um procedimento em um arquivo específico, inclua a cláusula IN no comando DO.

Para obter informações sobre o uso do comando PROCEDURE ao criar classes, consulte Comando DEFINE CLASS.

# Exemplo

O exemplo a seguir ilustra como um procedimento pode ser chamado para realizar uma tarefa discreta, como fazer uma entrada em um arquivo de log. O procedimento abre o arquivo de log (que se presume existir no exemplo), constrói uma entrada baseada em informações passadas em parâmetros, grava a entrada e fecha o arquivo. O procedimento é chamado com um comando DO semelhante ao do topo do programa.

```foxpro
DO MakeLogEntry WITH "Logged in", "jsmith"
PROCEDURE MakeLogEntry
 PARAMETERS message, username
 pnHandle = FOPEN("LOG2.TXT",2)     && Assume the file exists
 pnSize = FSEEK(pnHandle,0,2)           && Move to end of file
 logEntry = dtoc(date())+","+time()+","+username+","+message
 =FPUTS(pnHandle, logEntry)
 =FCLOSE(pnHandle)  && Close file
ENDPROC
```

O exemplo a seguir mostra como um procedimento pode ser chamado para retornar um valor.

```foxpro
SET CENTURY ON
? longdate(({^1998-02-16}))  && Displays Monday, February 16, 1998
PROCEDURE longdate
 PARAMETER mdate
 RETURN CDOW(mdate) + ", " + MDY(mdate)
ENDPROC
```
