# Comando SHOW GETS

Incluído para compatibilidade com versões anteriores. Use o método Refresh (Visual FoxPro) para exibir novamente todos os controles em um formulário ou formset após alterar as propriedades do controle.

Exibe novamente todos os controles @ ... GET.

```foxpro
SHOW GETS
	[ENABLE | DISABLE]
	[LEVEL expN1]
	[OFF | ONLY]
	[WINDOW window name]
	[LOCK]
	[COLOR SCHEME expN2
	| COLOR color pair list ]
```

# Observações

SHOW GETS exibe novamente todos os controles (caixas de seleção, campos, invisíveis, botões push ou de opção, listas, pop-ups, spinners ou regiões de edição de texto). Quando os valores nos campos @ ... GET mudam (o cursor se move para um novo registro, por exemplo), SHOW GETS atualiza os valores dos campos @ ... GET. Os controles podem ser habilitados ou desabilitados quando são exibidos novamente.

Uma rotina contendo SHOW GETS pode ser usada para exibir novamente os controles @ ... GET. Uma rotina GET LEVEL VALID ou WHEN, ou uma rotina READ LEVEL ACTIVATE ou DEACTIVATE pode conter SHOW GETS.

READ suporta uma cláusula SHOW que executa uma rotina sempre que SHOW GETS é emitido. Uma rotina READ SHOW é frequentemente usada para atualizar a saída de @ ... SAY. Quando SHOW GETS é emitido, a rotina SHOW é executada e todos os controles são exibidos novamente.

A emissão de SHOW GETS redefine UPDATED() para falso (.F.).

SHOW GETS vs. SHOW GET e SHOW OBJECT

 Todos os controles criados com @ ... GET são exibidos novamente com SHOW GETS. Controles individuais são exibidos novamente com SHOW GET ou SHOW OBJECT. SHOW GETS executa a rotina SHOW de nível READ. SHOW GET e SHOW OBJECT não executam.

 SHOW OBJECT é semelhante a SHOW GET, exceto que SHOW OBJECT referencia controles pelo número do objeto, e SHOW GET referencia controles por var, a variável de memória, elemento de matriz ou campo especificado quando o controle é criado. Para obter mais informações sobre numeração de controles, consulte OBJNUM() ou _CUROBJ.

ENABLE | DISABLE

 Incluir ENABLE permite que todos os controles sejam selecionados ou escolhidos. Incluir DISABLE impede que todos os controles sejam selecionados ou escolhidos e os exibe novamente em cores desabilitadas.

LEVEL expN1

 Você pode aninhar READs emitindo @ ... GETS e um READ em uma rotina chamada em um READ ativo. READs podem ser aninhados até cinco níveis.

 Se você não incluir uma cláusula LEVEL, SHOW GETS assume o nível READ atual por padrão. Inclua uma cláusula LEVEL para exibir novamente controles em um nível diferente do nível atual. A expressão numérica expN2 pode assumir o valor 1, 2, 3, 4 ou 5, correspondendo ao nível READ dos controles a serem exibidos novamente. RDLEVEL() retorna o nível READ atual.

OFF | ONLY

 Quando OFF é incluído, SHOW GETS executa apenas a rotina READ SHOW e não atualiza nenhum controle. Quando ONLY é incluído, SHOW GETS atualiza apenas os controles e não executa a rotina READ SHOW.

WINDOW window name

 Controles podem ser colocados em janelas diferentes e ativados com um único READ. A cláusula WINDOW permite exibir novamente controles em uma janela específica sem exibir novamente controles em todas as janelas. Especifique o nome da janela dos controles a serem exibidos novamente com window name. SYS(2016) retorna um asterisco (*) se você emitir SHOW GETS sem uma cláusula WINDOW. SYS(2016) retorna o nome da janela se você emitir SHOW GETS com uma cláusula WINDOW.

LOCK

 Quando um READ é emitido e uma tabela é aberta para acesso compartilhado em uma rede, o FoxPro pode tentar bloquear todos os registros envolvidos no READ. Se READ ou READ LOCK é emitido, o FoxPro tenta bloquear todos os registros envolvidos no READ. Se READ NOLOCK é emitido, o FoxPro não tenta bloquear os registros e torna todos os campos envolvidos no READ somente leitura.

 SHOW GETS assume o comportamento de bloqueio de registros do READ. Se READ ou READ LOCK é emitido, SHOW GETS tenta bloquear os registros envolvidos no READ. Se READ NOLOCK é emitido, SHOW GETS não tenta bloquear os registros, e todos os campos envolvidos no READ são tornados somente leitura.

 Se LOCK é incluído em SHOW GETS, SHOW GETS sempre tenta bloquear os registros envolvidos no READ. Emitir SHOW GETS LOCK permite substituir READ NOLOCK.

 Para obter mais informações sobre como o bloqueio de registros é tentado durante um READ, consulte READ neste manual.

COLOR SCHEME expN2 | COLOR color pair list

 Controles podem ser exibidos novamente nas cores que você especificar. Você pode especificar um esquema de cores ou uma lista de pares de cores. Para obter informações sobre cores de controles, consulte @ ... GET e a seção Controles neste manual.

# Exemplo

O exemplo a seguir cria uma janela de entrada de dados e uma janela de controle que usa DO para chamar procedimentos que movem você por CUSTOMER.DBF.

```foxpro
CLOSE ALL
SET TALK OFF
DEFINE WINDOW customer FROM 3,3 TO 13,57 ;
	FLOAT SHADOW DOUBLE
DEFINE WINDOW panel2 FROM 2, 61 TO 14,74 ;
	FLOAT SHADOW DOUBLE COLOR SCHEME 5
USE customer
ACTIVATE WINDOW customer NOSHOW
@ 3,3 SAY 'Company'
@ 3,14 GET customer.company SIZE 1,35
@ 5,3 SAY 'Contact'
@ 5,14 GET customer.contact SIZE 1,35
@ 7,3 SAY 'City/State'
@ 7,14 GET customer.city SIZE 1,21
@ 7,36 GET customer.state
@ 7,39 GET customer.zip
@ 0,3 SAY 'Customer #'
@ 0,15 SAY cno SIZE 1,6
@ 0,36 SAY 'Record #'
@ 0,46 SAY RECNO() SIZE 1,3
ACTIVATE WINDOW panel2
@ 1,2 GET act PICTURE;
	'@*VN Top;Prior;Next;Bottom;\?Quit' ;
	SIZE 1,8,1 DEFAULT 0 VALID actvalid()
READ CYCLE SHOW readshow() COLOR ,R/BG
RELEASE WINDOWS customer,panel2
FUNCTION actvalid
DO CASE
	CASE act = 1
		GO TOP
	CASE ACT = 2
		DO go_prev
	CASE ACT = 3
		DO go_next
	CASE act = 4
		GO BOTTOM
	CASE act = 5
		CLEAR READ
ENDCASE
SHOW GETS
RETURN 0
FUNCTION readshow
STORE WOUTPUT() TO currwind
IF SYS(2016) = 'customer' OR SYS(2016) = '*'
	ACTIVATE WINDOW customer SAME
	@ 0,15 SAY cno SIZE 1,6
	@ 0,46 SAY RECNO() SIZE 1,3
ENDIF
IF NOT EMPTY(currwind)
	ACTIVATE WINDOW (currwind) SAME
ENDIF
RETURN .T.
PROCEDURE go_prev
SKIP -1
IF BOF()
	GO TOP
ENDIF
RETURN
PROCEDURE go_next
SKIP 1
IF EOF()
	GO BOTTOM
ENDIF
RETURN
```
