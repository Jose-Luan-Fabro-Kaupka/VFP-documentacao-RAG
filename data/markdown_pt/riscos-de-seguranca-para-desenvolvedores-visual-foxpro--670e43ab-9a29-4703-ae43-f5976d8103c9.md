# Riscos de segurança para desenvolvedores Visual FoxPro

É importante compreender questões de segurança ao desenvolver e implantar aplicativos. Para informações gerais sobre o desenvolvimento de aplicativos seguros, consulte o site da Microsoft em http://msdn.microsoft.com/security.

Os desenvolvedores precisam estar cientes das seguintes questões de segurança e práticas recomendadas específicas ao desenvolver aplicativos Visual FoxPro:
 - Valide os valores de entrada de parâmetros antes de avaliá-los. Ao passar valores de entrada do usuário como parâmetros para comandos como instruções SQL, você deve incluir código para verificar se esses valores não contêm expressões prejudiciais, como aquelas que podem causar violações de acesso. Evite usar caixas de texto simples para entrada de parâmetros quando possível e escolha elementos de interface do usuário que você possa controlar mais facilmente, como caixas de listagem, grades como caixas de listagem ou controles OptionGroup. Se você precisar confiar em entrada digitada pelo usuário como parâmetro, por exemplo, para executar comandos, sempre analise a entrada em busca de parênteses (()) . Isso garante que os usuários não insiram dados que possam ser interpretados pelo Visual FoxPro como uma expressão. Você também deve verificar a entrada em busca do e comercial (&), que é usado como caractere de substituição de macro. Cuidado Use extremo cuidado ao aceitar entrada digitada pelo usuário como parâmetros e passá-la para os seguintes elementos de linguagem: comando RUN ou !, função EVALUATE( ), função EXECSCRIPT( ), método _VFP .DoCmd, método _VFP.Eval e o caractere e comercial (&). Essa prática é recomendada apenas para desenvolvedores avançados que usam rotinas robustas de validação de parâmetros para analisar valores que possam causar danos ao aplicativo, ao computador do usuário ou à rede.
- Forneça menos flexibilidade aos usuários ao fornecer valores para instruções SQL SELECT. Ao usar métodos de servidor COM ou SQL Server que aceitam valores de entrada do usuário de uma instrução SQL SELECT, escreva código que evite dar ao usuário acesso a informações que devem ser protegidas, como o nome do computador, ou permitir ações indesejadas, como permitir que o usuário copie tabelas e bancos de dados.
- Defina os atributos do sistema de arquivos do contêiner de banco de dados (DBC) como acesso somente leitura. Se um DBC estiver definido como acesso leitura/gravação, os usuários podem modificar o código de eventos do DBC, como o evento DBC_BeforeOpenTables, para incluir código prejudicial, por exemplo, para formatar o disco rígido de um usuário ao abrir uma tabela no DBC. Se o DBC precisar ser modificado como parte da manutenção, um administrador de rede pode definir temporariamente o DBC com acesso leitura/gravação e depois redefini-lo como acesso somente leitura quando a manutenção terminar.
- Impedir que os usuários visualizem o código-fonte em seu aplicativo criptografando o aplicativo e removendo informações de depuração. Para proteger o código-fonte e remover informações de depuração, abra o projeto do aplicativo no Project Manager. Para criptografar o projeto do aplicativo e não incluir informações de depuração, selecione a caixa de seleção Encrypted e desmarque a caixa de seleção Debug info na caixa de diálogo Project Information. Em seguida, selecione a caixa de seleção Recompile All Files na caixa de diálogo Build Options e recompile o projeto clicando em Build na janela Project Manager. Na seção de configuração do aplicativo, inclua o comando SET DEBUG. A classe _cryptapi localizada na biblioteca de classes básicas ...\Ffc\_Crypt.vcx fornece acesso às rotinas da API Crypto do Windows para que você possa criptografar cadeias de caracteres, dados ou arquivos em seus aplicativos Visual FoxPro. Para obter mais informações, consulte Caixa de diálogo Project Information, Janela Project Manager, Caixa de diálogo Build Options e Comando SET DEBUG.
- Recomenda-se que você desenvolva aplicativos que usem configurações de usuário com privilégio mínimo. Não é necessário que o usuário faça login como usuário avançado ou administrador.
- Evite gravar nas chaves de registro HKEY_LOCAL_MACHINE e HKEY_CLASSES_ROOT. Em vez disso, grave apenas no hive HKEY_CURRENT_USER.
- Não crie nem atualize arquivos nos diretórios C:\Program Files (%PROGRAMFILES%) ou C:\Windows (%SYSDIR%). Em vez disso, grave os dados do usuário na pasta de aplicativos do usuário. Você pode usar a classe _commonfolder localizada na biblioteca de classes básicas ...\Ffc\_System.vcx para obter o local da pasta de aplicativos do usuário.
- Ao criar servidores COM no Visual FoxPro, recomenda-se criar aplicativos COM+ para implantá-los, de modo que você possa impor segurança baseada em funções COM+.
