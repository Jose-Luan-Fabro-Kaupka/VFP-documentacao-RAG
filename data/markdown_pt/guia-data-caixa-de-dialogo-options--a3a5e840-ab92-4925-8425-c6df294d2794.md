# Guia Data, caixa de diálogo Options

Contém opções para controlar dados em tabelas.

Quando você escolhe Set As Default, que aparece em cada guia da caixa de diálogo, o Visual FoxPro salva todas as opções em todas as guias.
 **Open exclusive**
Especifica se o Visual FoxPro abre tabelas e bancos de dados exclusivamente, para que ninguém mais possa visualizá-los ou modificá-los enquanto você está trabalhando neles. Abrir arquivos exclusivamente pode resultar em melhor desempenho. Use esta opção ao processar um grande número de registros em circunstâncias em que outros usuários não precisam de acesso aos dados (como à noite). Esta opção corresponde ao Comando SET EXCLUSIVE .
**Show field names**
Especifica se o Visual FoxPro exibe um nome de campo como cabeçalho de coluna acima de cada campo na saída dos comandos AVERAGE Command , CALCULATE Command , DISPLAY Command , LIST Commands e SUM Command . Esta opção corresponde ao Comando SET HEADINGS .
**Prompt for code page**
Especifica se o Visual FoxPro solicita que você anexe uma página de código ao abrir tabelas que ainda não têm uma anexada. Esta opção corresponde ao Comando SET CPDIALOG .
**Ignore deleted records**
Especifica se o Visual FoxPro ignora registros marcados para exclusão ao executar comandos que usam uma cláusula de escopo. Se esta opção estiver desmarcada, o Visual FoxPro inclui os registros marcados. Esta opção corresponde ao Comando SET DELETED .
**Rushmore Query Optimization**
Especifica se o Visual FoxPro usa otimização Rushmore ao executar comandos que incluem uma cláusula FOR. Esta opção corresponde ao Comando SET OPTIMIZE . Para obter mais informações, consulte Optimizing Applications .
**Unique records in indexes**
Especifica se o Visual FoxPro permite registros com valores de chave de índice duplicados em um arquivo de índice. Se você escolher esta opção, apenas o primeiro registro contendo a chave de índice original é indexado. Esta opção corresponde ao Comando SET UNIQUE .
**Collating sequence**
Especifica uma sequência de ordenação (ordem de classificação) para campos de caractere em operações de indexação e classificação. Esta opção corresponde ao Comando SET COLLATE .
**Record counter interval**
Especifica quantos registros devem ser processados durante comandos como COPY TO antes que o Visual FoxPro atualize a exibição do contador de registros na linha de status. O intervalo é de 1 a 32.767 registros. Quanto maior o número especificado, maior o atraso entre atualizações, mas o comando pode executar mais rápido. Você deve escolher a opção Status Bar na guia View para que esta opção tenha efeito. Esta opção corresponde ao Comando SET ODOMETER .
**Memo block size (bytes)**
Especifica o tamanho do bloco em que o espaço em disco para campos memo é alocado. O valor inserido especifica o espaço mínimo em disco necessário para um campo memo e o tamanho pelo qual os campos memo aumentam conforme dados são adicionados a eles. Se você especificar um valor entre 1 e 32, o Visual FoxPro multiplica seu valor por 512 e aloca espaço em disco em um bloco desse tamanho. Se você especificar um valor maior que 32, o Visual FoxPro aloca blocos apenas desse tamanho; especificar um número maior que 32 pode economizar espaço em disco. Esta opção corresponde ao Comando SET BLOCKSIZE .
**Browse refresh interval (sec)**
Especifica com que frequência o Visual FoxPro atualiza a exibição de registros em uma janela Browse ativa, o que é útil em um ambiente multiusuário. Valores possíveis são 0 a 3600. Defina este valor como 0 para impedir atualizações. Defina este valor como um número alto para atualizar a janela Browse com menos frequência, o que pode aumentar o desempenho. Esta opção corresponde ao Comando SET REFRESH .
**Table refresh interval (sec)**
Especifica com que frequência o Visual FoxPro deve atualizar buffers de memória locais com dados atuais da rede, o que é útil em um ambiente multiusuário. Valores possíveis são -1, que especifica sempre ler dados do disco, e 0 a 3600. Valores fracionários até um mínimo de .001 são aceitos. Para impedir atualizações, defina este valor como 0. Para atualizar buffers de memória locais com menos frequência e aumentar o desempenho, defina este valor como um número alto. Esta opção corresponde ao segundo parâmetro do comando SET REFRESH. Para obter mais informações, consulte Comando SET REFRESH .

# Comparações de cadeias de caracteres
 **SET NEAR on**
Especifica que o Visual FoxPro posiciona o ponteiro de registro no registro correspondente mais próximo após um comando FIND ou SEEK sem sucesso. Esta opção corresponde ao Comando SET NEAR .
**SET EXACT on**
Especifica que o Visual FoxPro usa o comprimento total de ambas as expressões de cadeia de caracteres (exceto espaços à direita) ao usar o operador de comparação (=). Se você desmarcar esta opção, o Visual FoxPro para de comparar duas cadeias de caracteres quando o final da expressão no lado direito do operador de comparação (=) é atingido. Esta opção corresponde ao Comando SET EXACT . Observação Esta configuração não tem efeito nos resultados do operador =.
**SET ANSI on**
Especifica se o Visual FoxPro preenche cadeias de caracteres ao compará-las com o operador SQL =, que compara caractere por caractere até que a cadeia mais curta termine. Se você escolher esta opção, o Visual FoxPro preenche a cadeia mais curta com espaços, então uma comparação SQL falha ("Tommy" não é equivalente a "Tom "). Se você desmarcar esta opção, a cadeia mais curta não é preenchida, então cadeias de comprimentos diferentes podem ser equivalentes ("Tommy" é equivalente a "Tom"). Esta opção corresponde ao Comando SET ANSI .

# Bloqueio e buffering
 **Automatic file locking**
Especifica que o Visual FoxPro bloqueia automaticamente arquivos para certos comandos que não alteram dados, incluindo AVERAGE, COPY TO, INDEX, REPORT, SORT e TOTAL. Se você desmarcar esta opção, o arquivo não é bloqueado durante esses comandos, e outros usuários podem alterar registros enquanto seu comando está sendo executado. Esta opção corresponde ao Comando SET LOCK .
**Multiple record locks**
Especifica se o Visual FoxPro bloqueia vários registros simultaneamente. Se você desmarcar esta opção, o Visual FoxPro limpa todos os bloqueios atuais e permite bloquear apenas um registro por vez; o registro atual é desbloqueado quando você bloqueia o próximo. Esta opção corresponde ao Comando SET MULTILOCKS .
**Buffering**
Especifica para ambientes multiusuários se alterações de registro devem ser armazenadas em buffer localmente e, se sim, se de forma otimista ou pessimista. O buffering pode melhorar o desempenho e fornecer maior controle de simultaneidade. Você deve escolher a opção Multiple Record Locks para que esta opção tenha efeito. Corresponde à Função CURSORSETPROP( ) . As opções são: Off As alterações não são armazenadas em buffer, e atualizações de registro são feitas imediatamente no disco. Este modo é recomendado apenas ao trabalhar em um ambiente monousuário. Record (Pessimistic) O registro atual é bloqueado quando o usuário faz uma alteração nele, e as alterações são armazenadas em buffer. Outros usuários podem ler, mas não alterar o registro no disco. Quando o ponteiro de registro se move para outro registro, o registro atual é gravado automaticamente do buffer de volta para a tabela de origem e depois desbloqueado. O bloqueio pessimista de registro é útil para edição interativa em uma tabela sujeita a muitas atualizações por outros usuários. Record (Optimistic) As alterações de um único registro são armazenadas em buffer, mas não bloqueadas quando o usuário move o ponteiro de registro para o registro. Outros usuários podem ler e alterar o registro no disco. Quando o usuário move o ponteiro de registro para outro registro, o Visual FoxPro verifica alterações no registro atual em relação ao registro no disco. Se o registro no disco foi alterado, o Visual FoxPro oferece opções para descartar as alterações atuais ou sobrescrever o registro no disco. O buffering otimista de registro é recomendado principalmente ao atualizar tabelas com pouca atividade. Table (Pessimistic) As alterações de registro são armazenadas em buffer e bloqueadas quando o usuário move o ponteiro de registro para elas, e permanecem assim até que a Função TABLEUPDATE( ) seja chamada. O buffering pessimista de tabela é o modo mais seguro para atualizar vários registros em uma tabela, mas como bloqueia cada registro alterado, pode limitar o acesso de outros usuários aos dados. Portanto, é recomendado apenas para acelerar a entrada de dados quando os usuários inserirão novos registros em lotes, ou quando é essencial para o aplicativo que todos os registros em uso sejam mantidos exclusivamente pelo aplicativo. Observação Ao usar buffering de tabela, você deve executar TABLEUPDATE() para gravar alterações de registro em buffer no disco. Se não fizer isso, os registros alterados são descartados quando o usuário sai do Visual FoxPro. Table (Optimistic) As alterações de registro são armazenadas em buffer, mas não bloqueadas, quando o usuário move o ponteiro de registro para o registro. Outros usuários podem ler e alterar os registros no disco. Quando TABLEUPDATE( ) é executado, o Visual FoxPro verifica alterações em cada registro conforme o registro é gravado no disco; registros que foram alterados não são gravados. O buffering otimista de tabela é útil para otimizar o desempenho de atualização em tabelas com pouca atividade. Ao usar esta opção, execute TABLEUPDATE( ) com frequência para que as chances de registros em buffer serem alterados no disco sejam minimizadas. Observação Ao usar buffering de tabela, você deve executar TABLEUPDATE() para gravar alterações de registro em buffer no disco. Se não fizer isso, os registros alterados são descartados quando o usuário sai do Visual FoxPro.
**Reprocessing**
Especifica quantas vezes ou por quanto tempo o Visual FoxPro tenta bloquear um registro ou tabela que já está bloqueado por outro usuário. Esta opção corresponde ao Comando SET REPROCESS . As opções são: Attempt Lock (Default) . Tenta bloquear apenas uma vez. Attempt Lock (Automatic) . Continua tentando o bloqueio até ter sucesso ou até o usuário cancelar a tentativa pressionando ESC. Equivalente a SET REPROCESS TO AUTO. Wait for Lock . Continua tentando um bloqueio até o registro ficar disponível. Esta opção não fornece uma forma para o usuário parar de tentar bloquear o registro. Equivalente a SET REPROCESS TO -1. Retry Attempts . Tenta bloquear o registro ou tabela o número especificado de vezes. Se o bloqueio ainda não tiver sucesso, uma mensagem de erro é exibida. SET REPROCESS TO n , onde n é o número de tentativas de repetição. Retry Seconds . Tenta bloquear o registro ou tabela pelo número especificado de segundos. Se o bloqueio ainda não tiver sucesso, uma mensagem de erro é exibida. SET REPROCESS TO n SECONDS, onde n é o número de segundos para repetir.
