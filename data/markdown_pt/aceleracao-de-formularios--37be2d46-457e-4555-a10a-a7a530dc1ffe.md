# Aceleração de formulários

Ao projetar um formulário baseado principalmente em dados do servidor, adote uma abordagem minimalista para obter o melhor desempenho. Determine os dados e a funcionalidade necessários e adie a solicitação desses dados e funcionalidade ao servidor até que sejam solicitados pelo usuário. Solicitar dados do servidor usa tempo de processamento e cria tráfego de rede. Para solicitar menos dados em seus formulários:
 - Solicite o menor número possível de registros. Por exemplo, use um filtro ou consulta para limitar o tamanho do conjunto de registros. Certifique-se de que o servidor possa processar quaisquer restrições que você usar.
- Use o menor número possível de campos remotos em views subjacentes aos seus formulários.
- Use o menor número possível de formulários que acessam views remotas em seu conjunto de formulários. Quando você abre um conjunto de formulários, todos os formulários no conjunto de formulários são abertos e preenchidos com dados conforme aplicável. Ao limitar o número de formulários no conjunto de formulários, especialmente aqueles que devem se conectar a um servidor e recuperar dados remotos, você encurta o tempo que o conjunto de formulários leva para carregar.
- Use menos controles vinculados que acessam dados remotos. Cada caixa de combinação, caixa de listagem e grade vinculada a uma tabela ou consulta remota requer uma consulta separada ao servidor quando o formulário é aberto. Evite controles contendo totais, ou caixas de listagem e caixas de combinação que tenham grandes origens de linhas.
- Se os usuários precisarem comparar vários conjuntos de dados, considere armazenar os dados retornados pelo servidor em tabelas locais temporárias. Forneça um formulário no qual o usuário possa usar os dados armazenados anteriormente ou executar uma nova consulta.

# Armazenando tabelas de consulta localmente

Frequentemente, um aplicativo contém vários formulários que usam a mesma tabela remota. Se os dados na tabela não mudam com frequência, você pode acelerar o carregamento de formulários e reduzir a carga do servidor usando uma das seguintes técnicas:
 - Armazene tabelas que nunca mudam e não são muito grandes (como os nomes e abreviações das regiões ou estados do seu país) no banco de dados local do aplicativo Visual FoxPro. Se a tabela estiver unida em consultas ou views com tabelas remotas, você também deve manter uma cópia dela no servidor para evitar unir dados locais e remotos.
- Armazene tabelas que raramente mudam (como uma lista de prédios da empresa) tanto no servidor quanto no banco de dados local do aplicativo. Forneça uma forma para o usuário baixar a tabela quando os dados mudarem.
- Armazene tabelas que mudam ocasionalmente, mas não diariamente (como uma lista de funcionários em uma pequena empresa ou departamento) tanto no servidor quanto no banco de dados local do aplicativo. Seu aplicativo deve atualizar automaticamente a versão local cada vez que iniciar. Este método usa tempo extra quando o aplicativo inicia, mas acelera consultas enquanto o aplicativo está em execução.

# Exibindo campos somente quando solicitado

Exiba campos que demoram para recuperar dados do servidor, como campos Memo ou General, somente quando solicitados. Você pode usar as seguintes técnicas:
 - Se seu formulário for baseado em uma view, coloque campos Memo ou General fora da tela em outra página do formulário. Adicione um rótulo ao formulário, como "Page down to see notes and pictures," que informe ao usuário como exibir as informações. Defina a propriedade FetchMemo na view ou cursor como false (.F.), para que o Visual FoxPro não recupere campos Memo ou General até que sejam exibidos na tela.
- Defina a propriedade Visible como false (.F.) para controles vinculados a campos Memo ou General. Adicione um botão de alternância ou botão de comando que defina a propriedade como true (.T.), para que o usuário possa escolher visualizar o conteúdo desses controles.
- Exiba os campos mais importantes em um formulário principal e forneça um botão rotulado "More Information" que abra outro formulário contendo outros campos. Baseie o segundo formulário em uma view parametrizada pelo campo de chave primária no formulário principal. Por exemplo, suponha que você tenha um formulário principal baseado em uma view cujo instrução SQL SELECT inclui o código a seguir: SELECT customer_id, company_name, address, city, region, country FROM customers No formulário anterior, cust_id está vinculado a thisform.txtCust_id . Você poderia basear o segundo formulário na view a seguir, que é usada somente quando o usuário escolhe o botão "More Information": SELECT orders.order_id, orders.order_date, orders.shipper_id, ; employee.emp_id, employee.last_name, employee.first_name ; FROM orders, employee ; WHERE orders.cust_id = ?THISFORM.txtCust_id ; AND orders.employee_id = employees.emp_id
