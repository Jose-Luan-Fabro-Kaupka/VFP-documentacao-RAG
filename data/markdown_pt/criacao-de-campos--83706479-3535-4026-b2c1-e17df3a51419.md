# Criação de campos

Você pode definir campos especificando um nome de campo, um tipo de dados e uma largura de campo. Quando você cria uma tabela, precisa definir os campos que a tabela contém. Tabelas do Visual FoxPro podem conter até 255 campos.

> **Observação:** Se um ou mais campos podem armazenar valores nulos, o número máximo de campos é reduzido de 255 para 254.

A lista a seguir descreve os atributos gerais que você especifica ao criar um campo:
 - Nome do campo.
- Tipo de dados que o campo contém.
- Largura do campo.
- Número de casas decimais se o campo contém valores numéricos ou float.
- Um índice no campo.
- Se o campo aceita valores nulos.

Você também pode realizar as seguintes tarefas ao trabalhar com campos:
 - Especificar valores padrão para o campo.
- Adicionar comentários para o campo.
- Especificar máscaras de entrada para inserir e armazenar dados no campo.
- Definir valores com incremento automático em campos.

As seções a seguir descrevem considerações ao criar campos:
 - Considerations for Choosing Field Names
- Considerations for Choosing Data Types
- Considerations for Default Values in Fields

# Considerações para escolher nomes de campos

Para campos de banco de dados, o Visual FoxPro armazena os primeiros 10 caracteres do nome do campo no arquivo de tabela (.dbf) e o nome longo do campo no arquivo de banco de dados (.dbc). As regras para criar nomes longos de campos são as mesmas que para criar qualquer identificador do Visual FoxPro, exceto que nomes de campos de banco de dados podem conter até 128 caracteres. Para obter mais informações, consulte Creating Visual FoxPro Names.

No entanto, enquanto uma tabela estiver associada a um banco de dados, você deve usar os nomes longos de campos para referenciar campos de tabela, não os nomes de campos de 10 caracteres. Se você remover uma tabela de um banco de dados, os nomes longos dos campos são perdidos, e você deve usar os nomes de campos de 10 caracteres armazenados no arquivo de tabela (.dbf) como nomes de campos.

Se os primeiros 10 caracteres no nome longo não são únicos na tabela, o Visual FoxPro gera um nome de campo consistindo nos primeiros n caracteres no nome longo acrescentados por um número sequencial para um total de 10 caracteres. A tabela a seguir lista exemplos de nomes gerados.

| Nome longo | Nome curto |
| --- | --- |
| customer_contact_name | customer_c |
| customer_contact_address | customer_2 |
| customer_contact_city | customer_3 |
| ... | ... |
| customer_contact_fax | customer11 |

Em índices, nomes longos de campos podem consistir em caracteres, mas não números. No entanto, se você criar um índice usando nomes longos de campos e depois remover a tabela referenciada do banco de dados, o índice não funciona mais corretamente. Neste caso, você pode encurtar os nomes de campos no índice e depois reconstruir o índice, ou pode excluir o índice e recriá-lo usando nomes curtos de campos. Para obter mais informações, consulte Working with Table Indexes.

Para obter mais informações sobre como escolher nomes de campos, consulte How to: Name Fields.

# Considerações para escolher tipos de dados

Quando você escolhe o tipo de dados para um campo, lembre-se das seguintes considerações:
 - Os tipos de valores que o campo pode armazenar. Por exemplo, você não pode armazenar texto em um campo numérico.
- A quantidade de armazenamento que o campo precisa para armazenar valores. Por exemplo, qualquer valor com tipo Currency usa 8 bytes de armazenamento.
- Os tipos de operações que você deseja realizar em valores no campo. Por exemplo, o Visual FoxPro pode calcular a soma de valores com tipo Numeric ou Currency, mas não a soma de valores com tipo Character ou General. Dica Para números que você não pretende usar para cálculos matemáticos, por exemplo, números de telefone, use o tipo Character, não Numeric.
- A capacidade de indexar ou classificar valores no campo. Por exemplo, você não pode classificar ou criar um índice para campos com tipo Memo ou General.

Para obter mais informações sobre tipos de dados do Visual FoxPro, consulte Visual FoxPro Data and Field Types. Para obter mais informações sobre como escolher tipos de dados para campos, consulte How to: Choose Data Types.

# Considerações para valores padrão em campos

Especificar valores padrão para campos ajuda os usuários do aplicativo a inserir dados mais rapidamente, permitindo pular campos a menos que desejem alterar o valor padrão.

> **Dica:** Se uma regra de negócio para seu aplicativo exige que um campo contenha uma entrada, fornecer um valor padrão ajuda a obedecer essa regra usando uma regra em nível de campo ou de registro.

Por exemplo, suponha que uma empresa tem principalmente clientes domésticos. No formulário usado para inserir dados de novos clientes, você pode querer exibir o país para esses clientes como valor padrão no campo de país ou região. Se outros valores são necessários para o país ou região, o usuário pode substituir o valor padrão pelo valor apropriado.

Você pode especificar valores padrão que são valores escalares, como um número, ou expressões que avaliam para uma quantidade escalar. Você também pode especificar qualquer expressão FoxPro válida que retorne um valor consistente com o tipo de dados do campo.

> **Observação:** Ao especificar o valor padrão, o Visual FoxPro avalia o valor padrão ou expressão para o tipo de dados correto ao fechar a estrutura da tabela ou usar os comandos SQL CREATE TABLE ou ALTER TABLE. Se o tipo de dados da expressão não corresponder ao tipo de dados do campo, o Visual FoxPro gera um erro. Expressões que são funções definidas pelo usuário (UDF) ou contêm UDFs não são avaliadas; portanto, não geram erros.

O Visual FoxPro avalia o valor padrão ou expressão ao usar os comandos APPEND, APPEND BLANK ou SQL INSERT para atribuir valores a campos. Quando você atribui valores a campos usando os comandos APPEND FROM ou SQL INSERT, o Visual FoxPro aplica valores padrão a quaisquer campos que não são explicitamente atribuídos. No entanto, esses dois comandos não substituem valores existentes por valores padrão.

Você também pode usar valores padrão para preencher campos que não aceitam valores nulos. Quando você adiciona um novo registro, o Visual FoxPro aplica os valores padrão e depois verifica cada campo na ordem em que são definidos para dados ausentes. Isso garante que campos que não aceitam valores nulos possam ser preenchidos com valores padrão antes de aplicar a restrição de que os campos não podem ser nulos.

Se campos em suas tabelas aceitam valores nulos, você pode usar o valor nulo (.NULL.) como valor padrão. Independentemente de SET NULL estar ligado ou desligado, se você usar nulo (.NULL.) como valor padrão, o Visual FoxPro insere nulo (.NULL.) em campos para todos os comandos exceto APPEND BLANK. Para obter mais informações, consulte SET NULL Command e How to: Permit Null Values in Fields.

Se você não especificar um valor padrão, um valor em branco apropriado para o tipo de dados do campo é inserido, a menos que o comando SET NULL esteja definido como ON. Isso preserva a compatibilidade com versões anteriores.

> **Observação:** Quando você remove ou exclui uma tabela de um banco de dados, todos os valores padrão para campos nessa tabela são excluídos do banco de dados. No entanto, stored procedures referenciadas pelo valor padrão removido ou excluído permanecem mesmo depois que o valor padrão foi removido.

Para obter mais informações sobre como definir valores padrão para campos, consulte How to: Create Default Field Values.
