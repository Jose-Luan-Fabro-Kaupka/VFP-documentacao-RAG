# Usando GDI+ em relatórios

O modo de geração de relatórios assistido por objetos do Visual FoxPro 9 aproveita o Microsoft Windows GDI+ para renderizar em dispositivos de saída. O GDI+ oferece novas possibilidades para saída de alta qualidade e extensível, e também impõe algumas alterações no comportamento de saída nativo. Este tópico descreve alguns aspectos da criação de saída associada ao uso do GDI+.

# Recursos GDI+ na saída assistida por objetos do Visual FoxPro

Quando você usa o modo de geração de relatórios assistido por objetos do Visual FoxPro, a saída é renderizada por um objeto derivado de ReportListener. A tabela a seguir lista as formas pelas quais os recursos e o comportamento nativo do ReportListener são afetados pelo GDI+.
 **Renderização independente de dispositivo e de resolução**
O GDI+ fornece um objeto graphics, uma camada extra de abstração além do contexto de dispositivo do GDI. O objeto graphics é capaz de renderizar saída de forma idêntica em dispositivos distintos, como telas e impressoras. Você pode esperar um alto grau de consistência entre a saída de visualização e a de impressão no modo de geração de relatórios assistido por objetos do Visual FoxPro. Os métodos do objeto graphics para dispor texto e gráficos são independentes de resolução, de modo que o Visual FoxPro pode renderizar páginas em impressoras com resoluções diferentes, conforme as capacidades de cada impressora. Observação Como o Visual FoxPro respeita as resoluções de impressão disponíveis em cada impressora, você pode ver algum comportamento alterado em relatórios com ambientes de impressora salvos. Se a configuração de impressora com a qual o relatório foi salvo durante o design do relatório tinha uma resolução diferente da impressora que você especifica ao executar o relatório, a página pode não ser dimensionada corretamente. No Visual FoxPro 9, você pode substituir instruções de configuração de impressora com instruções explícitas em um campo separado, incluindo instruções explícitas para usar uma resolução de impressão específica independentemente da impressora (supondo que a impressora suporte a resolução que você definir). No entanto, na maioria dos casos, você não precisa fazer isso; simplesmente remover o ambiente de impressora do relatório fornece melhores resultados. Dica No Visual FoxPro 9, diferentemente das versões anteriores, o ambiente de impressora não é salvo na definição de relatório ou etiqueta por padrão. Para obter mais informações sobre o uso de configurações de substituição para ambientes de impressora, consulte Understanding and Extending Report Structure . Para obter mais informações sobre ambientes de impressora em relatórios, consulte How to: Save the Printer Environment for Reports .
**Diferenças no kerning e nas larguras de texto em relação à saída em versões anteriores**
Os métodos independentes de dispositivo e resolução do GDI+ para desenhar texto garantem que uma cadeia de caracteres específica se encaixará no mesmo espaço retangular em um layout quando renderizada em dispositivos diferentes. No entanto, os algoritmos do GDI+ que medem cadeias de caracteres, tratam o kerning (ou espaçamento) de letras individuais em cadeias e alinham cadeias no retângulo de layout são significativamente diferentes dos algoritmos originais do Report Engine usados para essa finalidade. Se você definiu a largura de expressões com muita precisão em um relatório existente, em alguns casos os mesmos dados não caberão mais. Você pode conseguir ampliar as expressões adequadamente adicionando apenas alguns pixels. Você pode usar as opções Size and position in layout do Report Builder, convenientes para essa finalidade. Para obter mais informações, consulte General Tab, Report Control Properties Dialog Box (Report Builder) . Dica Como nas versões anteriores do Visual FoxPro, expressões numéricas que não cabem no retângulo de layout atribuído são representadas por asteriscos na saída do relatório, para evitar fornecer um número que parece correto, mas está truncado. Se você ver asteriscos em uma expressão ao alternar um relatório para o modo assistido por objetos, e se acha que o número deveria caber no espaço, verifique se ele tem um picture template atribuído. Todas as versões do Visual FoxPro usam o picture template para determinar quanto espaço o número precisa para exibição. Se você usou um template como 99,999.99 , por exemplo, sua saída pode ser exibida como asteriscos mesmo que o número real tenha menos dígitos. Para garantir que a saída seja exibida corretamente no modo assistido por objetos, você pode ampliar o elemento de layout o suficiente para exibir 99,999.99 com os atributos de fonte designados do elemento. No entanto, se o picture template tem mais dígitos do que os resultados de dados que você antecipa, pode ser suficiente remover um dígito do template. Para obter mais informações, consulte Format Expressions for Field Controls . Quando cadeias de caracteres não cabem no retângulo de layout atribuído, o GDI+ fornece uma forma de informar ao usuário que a saída completa não está sendo exibida. A classe ReportListener aproveita esse recurso do GDI+ para saída que não representa números, com suas opções StringTrimming, descritas na próxima seção. Observação O Report System do Visual FoxPro, em todas as versões, ignora o retângulo de layout ao exibir campos calculados que têm picture templates. Como resultado, as diferenças entre a saída assistida por objetos e a saída compatível com versões anteriores descritas aqui não se aplicam a campos calculados. Por exemplo, um campo definido como Sum e com picture template 999,999,999 em um retângulo de layout pequeno demais para caber todos os caracteres do template exibirá seu texto completo; não será truncado. Para obter mais informações, consulte How to: Perform Calculations in Field Controls e Format Expressions for Field Controls .
**Opções StringTrimming**
O GDI+ fornece várias formas de tratar texto que não cabe no retângulo de layout atribuído. A classe ReportListener expõe suas várias opções conforme descrito na tabela abaixo. Ao projetar um relatório ou etiqueta, o Report Builder permite escolher entre essas opções na caixa de diálogo Report Control Properties. Para informações adicionais sobre a seleção de uma das opções disponíveis ao projetar um relatório, consulte Format Tab, Report Control Properties Dialog Box (Report Builder) . Value StringTrimming Type 0 Not specified, default will be used. 1 StringTrimmingCharacter Trims strings that do not fit at the nearest character. 2 StringTrimmingWord Trims strings that do not fit at the nearest word. 3 StringTrimmingEllipsisCharacter Trims strings that do not fit at the nearest character and adds an ellipsis ( … ). 4 StringTrimmingEllipsisWord (Visual FoxPro default) Trims strings that do not fit at the nearest word and adds an ellipsis ( … ). Observação Truncar a cadeia de caracteres no nível de palavra, em vez de caractere, emula mais fielmente o comportamento de truncamento do Visual FoxPro ao executar relatórios e não estar no modo assistido por objetos. Adicionar a reticência permite que os usuários vejam quando algum conteúdo está ausente. Como o GDI+ requer um pouco mais de espaço para expressões de texto do que o GDI, essa configuração permite verificar relatórios mais antigos para expressões que precisam ser ampliadas para que a renderização GDI+ trate seu conteúdo. 5 StringTrimmingEllipsisPath Replaces an inner portion of strings that do not fit with an ellipsis ( … ). Observação Esse valor é útil para nomes de caminho e arquivo. Por exemplo, a cadeia de caracteres C:\PROGRAM FILES\MICROSOFT VISUAL FOXPRO 9\REPORTOUTPUT.APP pode ser renderizada como C:\PROGRAM FILES\ … \REPORTOUTPUT.APP .
**Recurso DynamicLineHeight**
O espaçamento de linha do GDI+ é o método padrão de tratamento de espaçamento de linha para objetos ReportListener que renderizam texto de várias linhas. O espaçamento de linha do GDI+ permite uma aparência mais refinada, desempenho mais rápido e menos páginas para o mesmo conteúdo de relatório do que os algoritmos originais de espaçamento de linha do Report Engine. No entanto, o espaçamento de linha do GDI+ altera a quantidade de espaço que seu texto ocupa no layout quando você compara os resultados renderizados com versões anteriores do Visual FoxPro. A estratégia de renderização do ReportListener para texto que abrange várias linhas altera-se conforme o valor de sua propriedade DynamicLineHeight. Esse valor determina se o ReportListener usa o espaçamento de linha padrão (dinâmico) do GDI+ conforme as características da fonte, ou o espaçamento de linha fixo compatível com versões anteriores usado pelo Visual FoxPro ao executar relatórios e etiquetas, mas não estar no modo assistido por objetos. Para obter mais informações, consulte DynamicLineHeight Property .
**Disponibilidade de imagens de página de saída**
Quando um aplicativo renderiza em uma superfície de desenho específica usando GDI+, o GDI+ fornece métodos para salvar o conteúdo da superfície de desenho em vários tipos de arquivo de imagem. O Visual FoxPro expõe essa capacidade no método OutputPage do ReportListener. Para obter mais informações, consulte OutputPage Method .
**Disponibilidade de valores de transparência em configurações de cor**
O GDI+ especifica cores usando componentes ARGB (alpha ou transparência, vermelho, verde e azul). Os arquivos de definição de relatório e etiqueta do Visual FoxPro não têm uma forma de armazenar o valor de transparência, de modo que as cores armazenadas nas tabelas .frx e .lbx são sempre completamente opacas ou transparentes. No entanto, o Visual FoxPro expõe os valores de transparência ao código ReportListener em tempo de execução, no evento EvaluateContents. Você pode usar esse evento para definir dinamicamente cores de texto e de fundo de texto com diferentes graus de transparência e causar mesclagens em elementos de layout sobrepostos e semitransparentes. Para obter mais informações, consulte EvaluateContents Event .

# Usando GDI+ em código do usuário durante execuções de relatório

Seu código pode aproveitar as capacidades do GDI+ em relatórios. O Visual FoxPro 9 inclui um conjunto de classes wrapper para a API GDI+ para facilitar o uso desses recursos. Para obter mais informações, consulte GDI Plus API Wrapper Foundation Classes.

Seu uso do GDI+ durante uma execução de relatório assume uma de duas formas:
 - Você usa GDI+ para renderizar na superfície de desenho que o ReportListener usa para saída nativa. Nesse cenário, você pode posicionar dinamicamente novos elementos de saída ou alterar os existentes diretamente no relatório em execução. A classe ReportListener expõe um handle para seu próprio objeto graphics, durante uma execução de relatório, para essa finalidade. Para obter mais informações, consulte GDIPlusGraphics Property . Como explicado nesse tópico e mostrado no código de exemplo do tópico, para usar o objeto graphics nativo do ReportListener, você deve usar funções baseadas na mesma cópia do arquivo GDIPLUS.DLL que o produto usa em código nativo. Para garantir que você use a cópia correta de GDIPLUS.DLL, use a sintaxe IN GDIPLUS.DLL sem caminho explícito em suas instruções DECLARE DLL. Para obter mais informações, consulte DECLARE - DLL Command .
- Você fornece ao objeto ReportListener um handle para um objeto graphics separado e solicita que ele desenhe uma página de saída nesse objeto graphics adicional. Nesse cenário, você não alcança seu objetivo atribuindo temporariamente um handle diferente à propriedade GDIPlusGraphics do ReportListener; por motivos de segurança, esse handle é somente leitura. Em vez disso, você fornece ao ReportListener o handle adicional como um dos parâmetros do método OutputPage. O handle GDIPlusGraphics do ReportListener e o fluxo de saída nativo permanecem inalterados por esse processo. Para obter mais informações, consulte OutputPage Method .
